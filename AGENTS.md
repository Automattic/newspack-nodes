# AGENTS.md — Newspack Nodes

A **WordPress-internal** runtime borrowing the node vocabulary of [Tachikoma](https://github.com/datapoke/tachikoma) (Node, Message, Router, `fill`/`sink`), not a standalone message bus. WordPress supplies its lifecycle: config in the **options table**, the reconcile safety net on **WP-Cron**, worker spawn, commands and SSE over the **REST API** behind **HMAC + nonce** auth, reader positions in **offsetlogs** on disk, and stats in **memcache**. It owns the substrate (Node, Message, Router, Topic, Partition, Worker, Fleet, REPL) and ships no application logic; applications such as `newspack-event-logger-nodes` compose Nodes on top.

Every node honors one contract, `fill( array $message ): void`, and connects two ways: **`sink`**, the node reference `fill()` forwards to, and **`target`**, a string path stamped into `message[TO]` when TO is empty (Tachikoma's `owner`; `edge` is not ported). `_router` dispatches by peeling `message[TO]`.

Perl Tachikoma (`services/tachikoma/sources/tachikoma/lib/Tachikoma/`) is the ground truth. Match Tachikoma's model; don't blind-copy its field names. The four deliberate divergences — KEY/VALUE fields, structured VALUE, JSON wire, no TM_PERSIST — are argued in `docs/tachikoma-lineage.md`.

Developer experience breaks ties and never dilutes fidelity to the model. The substrate forgives an adopter's predictable mistakes, such as naming a node twice or renaming a live one, and answers every real mistake with an error that teaches. Complexity stays in the substrate: a feature that would make every consumer add wiring adds it here instead, which is why a dashboard's whole lifecycle contract is the `teardown()` that `mountExospine()` returns.

## Workflow discipline (mandatory)

`~/.claude/rules/workflow-discipline.md` governs every code-writing turn, subagents included: invoke `superpowers:test-driven-development` before any code, seed each failing test with values distinct from every default and fallback, and carry that file's verbatim TDD phrase into every subagent prompt. Subagents never commit; main Claude runs the gauntlet, ending in `/code-review`, then commits. At runtime, read required config through the fail-loud `Config::value()`, never `$config['key'] ?? default`.

## Code Style

WordPress VIP Go, enforced by `phpcs.xml.dist`: `snake_case`; Yoda conditions; `[]` arrays, arrow functions and spread allowed; tab indent and spaces inside parens (`function_name( $param )`); PHP 8.2+, constructor promotion where it shortens, PHPDoc on public methods. An unused local is an error (`VariableAnalysis`), because PHPStan cannot see one. Commits are conventional (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`).

**Comments** are gated by `scripts/lint-comments.{php,mjs}` inside `lint:php` and `lint:js`. An inline comment is one line of at most 80 columns, and two adjacent comment-only lines fail however short they are: collapse them, promote them to a docblock, or open the first line with `@longform`. At class-body level the only comment allowed is a docblock directly above its declaration. `@longform` marks inline comments only; a docblock line opening with it is an error, as is a description below a docblock's tag block (a `##` line, as in a WP-CLI `## OPTIONS` section, is exempt). Directive comments and the test and generated trees are exempt. The PHP half holds docblock generics tight (`array<string,mixed>`), and `--fix` rewrites them. A plugin's root `<slug>-config.php` takes a ledger rule instead: every comment run must contain, or sit directly above, a `'key' => value,` entry, and only the entry's own lines may exceed 80 columns.

The `nodes-workflow` skill carries the full test, deploy and restart loop. Three rules hold everywhere:

- **A test never waits in real time.** It drives a seam — `use_loop_time()` binds `Core::$clock` and `Event_Framework::$sleep` — rather than buying time with `#[Medium]` or `#[Large]`; `failOnRisky` fails a test that breaks its 10-second budget.
- **Most PHP dead-code findings here are live**: public API, WP-CLI entry points, JS–PHP wire constants and test seams. Verify every call path (siblings, JS, dynamic) before deleting.
- **Nothing automatic runs the bundled example's JS tests.** jest ignores `/examples/`, so a change under `src/shared/` or `src/runtime/` can break `examples/example-ai-newsletter`'s dashboard suites with every gate green. Run `npm run test:js` from that directory, with both trees installed, after such a change.

`pre-commit` syncs the shared tooling, runs the private-data gate over the staged diff where `pre-push.local` turns it on, then runs lint-staged (PHPStan included, and `scripts/lint-english.mjs`, the prose gate, over every staged file); `commit-msg` runs the private-data gate over the message on the same terms, then commitlint. `pre-push` runs the private-data gate over every pushed commit on the same terms, `scripts/lint-docs.sh` — a grep gate holding `docs/`, `README.md`, this file and `.claude/skills` to the runtime — `scripts/lint-english.mjs` over the whole repo, the JS suite with its 90% per-file gate, and the gates' self-tests on every push, then the PHP, JS or SCSS gates the push touched.

This repo holds the **authoritative copy of the shared `scripts/`**. Every sibling vendors a copy, which `scripts/sync-shared-scripts.sh` refreshes from here in each sibling's `pre-commit` whenever `../newspack-nodes` exists. Edit the copy here. `scripts/lib/coverage-php.sh` is the one choice of coverage driver: every plugin's `tests/run-coverage.sh` sources it, so changing the driver is an edit to that file alone. `pre-push` is shared too, and fails a push without the `scripts/pre-push.local` it sources, which the sync never touches. Each plugin's `.local` declares six constants — `PLUGIN_SLUG`, `CONTAINER`, `DEPLOY_CONTAINER`, `DEPLOY_SCRIPT`, `TEST_DIR_IN_CONTAINER` and `COVERAGE_DIR` — and two slot functions: `push_gates` runs after the shared gates, and `container_gates` after the coverage suite. A seventh constant, `readonly PRIVATE_DATA_GATE=1`, turns the private-data gate on; `newspack-nodes`, `newspack-intelligence`, `newspack-event-logger-nodes` and `newspack-cache-cozy` set it, and pyrobase, nuclear-gyrobase and community leave it unset. All three hooks read it the same way, the one line through `scripts/lib/private-data-gate.sh`, so `pre-commit` and `commit-msg` never source the `.local`. Unset or `0` skips the gate, which only `pre-push` reports, in one line; any other value, a trailing comment or a second setting fails the hook, naming the constant and the file. The hook passes `-e WP_ABSPATH` to the coverage suite's `docker exec`, so a `.local` that exports `WP_ABSPATH` hands it to the suite. A `.local` may also set `DEFERRED_GATES`, a bash array naming shared gates the plugin does not pass yet, from the hook's `deferrable` list: `js-coverage-gate`, `wp-pin`, `lint:php`, `lint:js`, `lint:types`, `lint:scss` and `coverage-gate`. The hook empties the array before it sources the `.local` and makes it read-only once validated, so neither the environment nor a gate slot can change the list. A deferred gate still runs wherever it would have run. While it fails, the push goes on: the hook shows the last 40 lines of its output, naming the `mktemp` log under `$TMPDIR` that holds the rest, then prints `<gate> deferred by pre-push.local: still failing`. A gate that cannot run (exit 126, 127 or a signal), or whose log cannot be created, fails the push instead. Once it passes, the push fails with `<gate> passes; remove it from DEFERRED_GATES in pre-push.local`, so each gate comes online on the first push after it passes. A name outside the list fails the push. None of the siblings sets the array. A gate that runs a `scripts/` file is one `script_gate` line, and pyrobase's and nuclear's date_math parity is one `date_math_parity <side>` line. The shared gates include `check-substrate-floor.sh`, which passes at once in a plugin declaring no floor. This repo's `push_gates` runs the shared tooling's self-tests, which belong here alone: the sync vendors that tooling byte for byte but leaves out every `test-*.sh`. `.shellcheckrc` rides along so shellcheck follows the hook into its `.local`. So does every `Sniffs/<Category>/<Name>Sniff.php`, which each plugin's `phpcs.xml.dist` references by path, putting it into `lint:php`: `Sniffs/WP/AbspathGuardSniff.php` reports any ABSPATH guard not written `\defined( 'ABSPATH' ) || exit;`, and phpcbf rewrites it. `lint-private-data.py` is the private-data gate, run with `python3 -I` where `PRIVATE_DATA_GATE` turns it on: it holds what a change adds — the staged diff's added lines and new paths, a commit message, or what a push carries: each pushed commit's message, added lines and new paths, a merge's diff against its first parent, each ref's local and remote names and each annotated tag's message — to a private pattern list that never enters any repo, a `class<TAB>regex<TAB>replacement` TSV whose first two columns the gate reads, from `$NEWSPACK_PRIVATE_PATTERNS`, else `${XDG_CONFIG_HOME:-$HOME/.config}/newspack/private-patterns.tsv`. A finding names the kind of place — a file and line, an added path, a commit's message, a ref's name, a tag's message — and the pattern's class, never the value or the regex, and a line in a file whose own path is private is named without the path. A missing list fails loud, naming the path, and an empty file there satisfies the gate on a machine with no private list; a symlink whose target is missing fails naming both, with no empty-file hint to write through it. A finding exits 1; a list, usage or git error exits 2, which `pre-push` reports as a gate that could not run. None of the workflows runs a hook, so CI never runs it: the list exists only on a maintainer's machine. `lint-english.mjs` holds comments, Markdown and HTML to the house prose rules, and each plugin runs its own vendored copy. A hit in a vendored `scripts/` file counts wherever the gate reads it, as `lint:shell` and the comment gate count one; the file is fixed here, and the next sibling commit syncs it. A false positive is carved out in the rule's `keep`, and the gate has no opt-out comment. `build.mjs`, `bump-version.sh`, `get-line-at-offset.sh` and every `test-*.sh` are never synced, and `render-diagram.sh` (a `docs/img/*.html` sheet to PNG, every sheet when given none; `CHROME=` overrides the browser path) reaches only a sibling with `docs/img/`, beside the `autocrop.py` it calls.

## Versioning & Release

Change the version only through `./scripts/bump-version.sh <version>`: it rewrites the `Version:` header, `NEWSPACK_NODES_VERSION`, `package.json` and the `SUBSTRATE_VERSION` banner in `src/build-kit/index.mjs`, and syncs `package-lock.json`. Pushing a strict `v<major>.<minor>.<patch>` tag runs the Release workflow, which builds every zip through `build-release.sh`, the one definition of archive contents, and publishes. `/release-event-logger newspack-nodes <version>` is the runbook.

**A signature change raises every consumer's `version_at_least()` floor.** Change the signature outright, update every caller in the sibling plugins in the same pass, and raise each caller's floor to the release carrying the change, so a consumer meeting an older substrate goes dormant instead of fataling. Neither a default parameter nor a shim keeps the old call working: a default that reads nothing is fail-silent. `scripts/check-substrate-floor.sh` measures a consumer's floor against every substrate method, constant, static property, class, interface and trait it reaches — a lower bound, because it drops any access PHPStan cannot pin to one class and reads no type hint — and `docs/upgrading.md` lists the rewrite.

Each is an ADR with its context, alternatives and reopen condition in **[`docs/architecture-decisions.md`](docs/architecture-decisions.md)**. "Decision N" here and in code comments means **ADR-N**. ## Layout

Each class's docblock and `docs/architecture-guide.md` carry the mechanism; this table orients and names the rules a change must keep.

| Path | What |

## Common Pitfalls

- **`@wordpress/*` is pinned exactly to the `wp-7.0` dist tag; never bump it to close an advisory.** `scripts/lint-wp-pin.mjs` fails a push when a declaration carries a range or the lock resolves elsewhere. The build externalizes these packages to `wp.*`, so a bump ships no code: it only moves the API you compile and test against ahead of the one the browser runs, and a changed component then passes every gate and breaks at runtime. Dismiss an advisory reachable only past the pin; npm `overrides` cannot scope around it, because it matches by package name across the whole tree. Move the family together, and only when the WordPress target moves (`npm view @wordpress/<pkg> dist-tags --json` against `wp core version`). Tooling packages are not pinned.
- **Five `Config_System` files stay Core-free** — `field`, `schema`, `options-overlay`, `reset-gate` and `field-reset-assets` — because pyrobase's `tests/load-config-system.php` loads them without the substrate. Never call `Core::` or another substrate class from them; `settings-renderer` and `restart-planner` may.
- **Messages are arrays, not hashes.** Index with the `Message::*` constants: `$message['type']` appends an eighth key that `packed()` drops. A TM_INFO or TM_REQUEST VALUE is a string, except a Table's `ADD` and `SADD` and a Row_Table's `ROWS` (ADR-23), and structured data takes TM_STRUCT. A multi-field one is a flat `KEY VALUE KEY VALUE` string of whitespace-free tokens, as `SSE_Out_Node::build_connected_msg()` mints it; `set_state()` follows the same rule.
- **Pick the `Core` coercion by its guard.** `as_*` cast leniently (`as_int('42')` is 42, `as_int(true)` is 1); `num_int` / `num_float` validate numerics, sending bools and `'12abc'` to the default, and belong on arithmetic paths; bare `str` / `arr` / `int` pass only the exact type, so `int()` on a JSON numeric string returns the default. An operator-supplied value wants the refusing `canonical_decimal()` instead, because every other family turns `--partition=abc` into p0: a WP-CLI flag reads through `Command_Args::option_int()` and refuses with `CLI::require_flag_int()`. A command argument or a positional `make_node` token declares its `type` in `node_schema()` and lets the binder or `parse_schema_args()` refuse it; never hand-parse what the schema declares. Test presence with `has_value()` (Perl `length()`) wherever `'0'` is legitimate — a partition, a KEY, a count — because `if ( $s )` drops it.
- **Sources stamp FROM; forwarders don't.** A node that mints a message stamps its own name — Shell `_output/_cli:<pid>/_output`, an interpreter `$this->name`, Timer, Tail and Consumer at their boundary — even on a message expecting no reply, because a misdirected command is traced by FROM. Tee, Hook and application relays pass FROM through. Transports (`HTTP_Out`, the SSE relays, a Partition) carry all seven fields verbatim and invent no addressing (ADR-2); when a caller breaks the contract, fix the caller, never the transport.
- **A reply is already addressed — never correlate it.** The server replies TO=FROM, so the reply lands on the node that minted the command, and its `fill()` handles it. Never mint an op-id into `message[ID]`, keep a promise registry, return a Promise from a transport, or use KEY as a demux discriminator. Needing to tell N replies apart means one node is doing N jobs: split by job, never by subject, because the subject rides in the address — FROM `vault:test:in/spoke-01` echoes back to `vault:test:in` with `spoke-01` left in TO. `HTTP_Out` still batches every node's commands into one POST per tick (ADR-7), and `scripts/lint-contract.mjs` refuses the JS correlation shapes.
- **`stamp_message()` drops instead of stamping a bad FROM**: when the node has no name (mid-construction or post-rename), and when FROM would exceed `MAX_FROM_SIZE` (1024), which stops path explosion on cycles. Keep the rate-limited drop.
- **A self-pacing node holds a RECURRING timer; `oneshot` is for single wakeups.** `fire_cb()` disarms a oneshot before dispatch, so a node that re-arms one at the bottom of `fire()` leaves the loop after its first early return or throw. Call `set_timer( $next_ms )` only when the interval changes, stop explicitly with `stop_timer()`, and keep every other arming site (boot, play) recurring too. `Durable_Reader::fire()`, `Remote_Consumer_Node::fire()` and `Stdin_Node::fire()` are the models; Partition's debounce and `HTTP_Out`'s flush are the only legitimate oneshots, and the JS `TimerNode` follows the same rule. A slow drain is a cadence bug: re-arm faster rather than `while`-draining a backlog inside one `fire()`, which blocks every other node and breaks `line_mode`'s one line per cycle. A tick that paces a channel, such as `Remote_Source`'s heartbeat, is not the pump's rate.
- **Never guard a runtime invariant.** `_router` exists in every real graph, so `Timer_Node::set_timer()` throws when a hitchhike finds none. A guard for an impossible state hides the breakage. When a unit test lacks the invariant, stand the node up as a real graph does; if that means editing many tests, rethink the new coupling.
- **Never hardcode a partition's place in a path.** `{partition}` may sit anywhere in a `.tsl` path (`requests.p{partition}`, `{partition}-requests`), so a `.p{N}` literal or a `\.p\d+$` regex misses other layouts. Resolve directories through `Topology_Analyzer::resolved_resource_dirs()`, and prefer the names a live worker reports over re-deriving them from disk.
- **Only the client heartbeat refreshes an SSE slot's TTL.** `SSE_Out_Node::$check_slot` only checks; the `workers heartbeat` command (`SSE_Slot_Pool::touch()`) refreshes. The pool is the rate limit, and a refresh on check would let an abandoned stream hold its slot forever. `SSE_Slot_Pool::ttl()` floors the TTL at 45 s, three `Remote_Source_Node::HEARTBEAT_INTERVAL`s. The browser's `_heartbeat` and `Remote_Source`'s poke are both load-bearing.
- **Release the worker lock before spawn.** `Worker_Base::execute()` runs `release()`, then `self_respawn()`. Reversed, the successor's acquire hits the held lock and skips, idling the slot until a peer rescues it.
- **Internal HMAC tokens accept two windows**, the current and previous 10-second ones. Don't tighten to one: the race tolerance is intentional. Purposes are separated in the hash, so a token for one endpoint never validates at the other.
- **Partition and Topic pack ALL message types**, TM_REQUEST, TM_ERROR and TM_EOF included, because IPC rides on them: `request_node`, `send_eof`, attached-mode errors, and the cli's drain on stdin close, where the interpreter bounces TM_EOF back TO=FROM and the cli's Dumper exits on the echo (5 s fallback). `Log` alone drops those three.
- **Skip readline when STDIN isn't a TTY.** `readline_callback_read_char()` reads the TTY layer, so piping into `wp nodes cli` without the gate burns 100% CPU. Keep the gate.
- **`Command_Interpreter_Node` only handles a TM_COMMAND with an empty TO and no TM_RESPONSE bit.** A non-empty TO means the message is in transit, so the interpreter forwards it to Router; dispatching on it would make every interpreter in a path-routed graph eat commands meant for peers downstream. The response-bit check stops a successful reply (`TM_COMMAND|TM_RESPONSE`) whose TO is already peeled from re-entering the command table.
- **An active topology that will not read fails loud, never silently.** A name with no matching `.tsl`, or a broken include, surfaces as a critical `worker-liveness` row, an `unreadable` entry in `dump_graph`, a `wp nodes status` warning, and a raise from every spawn pass, restart and retention sweep. A top-level boundary reports, never raises — `Worker_Should_Stop::report()`, one stderr line per cause with its file and line: the minute pass writes `<step>: <cause>` behind its `reconcile[<pid>]` process label, BEFORE `after_reconcile` fires; a settings save in wp-admin writes `settings: <key>: <cause>` and a settings error on the page; a request's exit wake flush writes `wake: <dir>: <cause>`; and the SSE stream logs `stream: <subs>: <cause>` and answers a generic `500 sse_subscription_unavailable`. A stale name in the `topologies` config key therefore fails every spawn pass until it is removed.
- **A refusal THROWS; a `return` is a result.** Command handlers throw freely and `interpret()` wraps the throw as TM_COMMAND|TM_ERROR, so do not add a per-command `try`/`catch`. The reply's words are `Core::caller_message()`'s: a refusal (an `\Exception`) reads as thrown to every caller, while an engine `\Error` or a driver's exception, anywhere down its chain or among a `Failures`' members, reads as thrown only to a caller `Capabilities::command_holds( MANAGE )` admits — a logged-in user holding manage under the session scope, or a worker's command whose session allows it — and as `<what>: internal error; the reason is in the server's log` to everyone else, an anonymous request outside a worker included, with the class, message, file and line on stderr. Any other surface that turns a throwable into caller-facing text — an MCP tool error, a listing row, a REST body, an admin notice — goes through the same helper. Every refusal raises — `usage: …`, `unknown node/class/formatter`, `no such topic`, a secure-level denial — because one returned as a string is indistinguishable from success. `remove_node`'s per-name refusals, `dump_node` with no name, and `Log_Sources`' unavailable catalog rows are existing carve-outs, not shapes to copy.
- **A constructor sets `$this->arguments`.** The base `dump_config()` reads it to emit a round-trippable `make_node` line; forget it and the round trip builds a different node. State a COMMAND sets needs an override that calls `parent::dump_config()` and appends its own `config_line()`s, as `Partition`, `Topic`, `Consumer`, `Remote_Source` and `Settings_Sync` do.
- **`Log` is a `Partition` subclass** with the same segments, rotation, retention, rotate lock and 4 KB cap. It differs three ways: it writes the message VALUE rather than the packed envelope, lays segments out as `{file}.0`, `{file}.1`, … with no bare `{file}`, and drops TM_ERROR, TM_EOF and TM_REQUEST. Args: `make_node Log <name> <file> [segment_size] [min_segments] [num_segments] [max_segments] [min_lifetime] [lifetime]`.
- **`Echo` drops a TM_ERROR with an empty TO**, which would otherwise bounce to a producer not expecting it. Keep the drop if you change Echo's routing.
- **The "Nodes" wp-admin page is the station**, and its tabs are station tabs (`src/station/`, `host: 'station'`, `newspack_nodes/station_tab_bundles`). "Hub" means the aggregating site of hub-and-spoke, "DevTools" the browser's panel, and "debug overlay" the floating panel.
