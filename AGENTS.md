# AGENTS.md — Newspack Nodes

A **WordPress-internal** runtime borrowing the node vocabulary of [Tachikoma](https://github.com/datapoke/tachikoma) (Node, Message, Router, `fill`/`sink`), not a standalone message bus. WordPress supplies its lifecycle: config in the **options table**, the reconcile safety net on **WP-Cron**, worker spawn, commands and SSE over the **REST API** behind **HMAC + nonce** auth, reader positions in **offsetlogs** on disk, and stats in **memcache**. It owns the substrate (Node, Message, Router, Topic, Partition, Worker, Fleet, REPL) and ships no application logic; applications such as `newspack-event-logger-nodes` compose Nodes on top.

Every node honors one contract, `fill( array $message ): void`, and connects two ways: **`sink`**, the node reference `fill()` forwards to, and **`target`**, a string path stamped into `message[TO]` when TO is empty (Tachikoma's `owner`; `edge` is not ported). `_router` dispatches by peeling `message[TO]`.

Perl Tachikoma (`services/tachikoma/sources/tachikoma/lib/Tachikoma/`) is the ground truth. Match Tachikoma's model; don't blind-copy its field names. The four deliberate divergences — KEY/VALUE fields, structured VALUE, JSON wire, no TM_PERSIST — are argued in `docs/tachikoma-lineage.md`.

Developer experience breaks ties and never dilutes fidelity to the model. The substrate forgives an adopter's predictable mistakes, such as naming a node twice or renaming a live one, and answers every real mistake with an error that teaches. Complexity stays in the substrate: a feature that would make every consumer add wiring adds it here instead, which is why a dashboard's whole lifecycle contract is the `teardown()` that `mountExospine()` returns.

## Workflow discipline (mandatory)

`~/.claude/rules/workflow-discipline.md` governs every code-writing turn, subagents included: invoke `superpowers:test-driven-development` before any code, seed each failing test with values distinct from every default and fallback, and carry that file's verbatim TDD phrase into every subagent prompt. Subagents never commit; main Claude runs the gauntlet, ending in `/code-review`, then commits. At runtime, read required config through the fail-loud `Config::value()`, never `$config['key'] ?? default`.

## Code Style

WordPress VIP Go, enforced by `phpcs.xml.dist`: `snake_case`; Yoda conditions; `[]` arrays, arrow functions and spread allowed; tab indent and spaces inside parens (`function_name( $param )`); PHP 8.2+, constructor promotion where it shortens, PHPDoc on public methods. An unused local is an error (`VariableAnalysis`), because PHPStan cannot see one. Commits are conventional (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`).

**Comments** are gated by `scripts/lint-comments.{php,mjs}` inside `lint:php` and `lint:js`. An inline comment is one line of at most 80 columns, and two adjacent comment-only lines fail however short they are: collapse them, promote them to a docblock, or open the first line with `@longform`. At class-body level the only comment allowed is a docblock directly above its declaration. `@longform` marks inline comments only; a docblock line opening with it is an error, as is a description below a docblock's tag block (a `##` line, as in a WP-CLI `## OPTIONS` section, is exempt). Directive comments and the test and generated trees are exempt. The PHP half holds docblock generics tight (`array<string,mixed>`), and `--fix` rewrites them. A plugin's root `<slug>-config.php` takes a ledger rule instead: every comment run must contain, or sit directly above, a `'key' => value,` entry, and only the entry's own lines may exceed 80 columns.

```bash
npm install && composer install && npm run build   # fresh clone; composer install also sets core.hooksPath=scripts
composer dump-autoload -o     # after adding or renaming a Node class: make_node and the palette read the classmap
cd tests && ../vendor/bin/phpunit --enforce-time-limit --filter <Class>   # the vendored 10.5.x only
npm run test:js
npm run lint:php              # phpcs, then the PHP comment gate
npm run lint:js               # eslint, the JS comment gate, then scripts/lint-contract.mjs (JS and PHP)
npm run lint:scss             # stylelint, then scripts/lint-styles.mjs
npm run lint:shell
npm run lint:types

npm run lint:deadcode:js      # knip; lint-staged runs it on staged .js/.jsx
```

The `nodes-workflow` skill carries the full test, deploy and restart loop. Three rules hold everywhere:

- **A test never waits in real time.** It drives a seam — `use_loop_time()` binds `Core::$clock` and `Event_Framework::$sleep` — rather than buying time with `#[Medium]` or `#[Large]`; `failOnRisky` fails a test that breaks its 10-second budget.
- **Most PHP dead-code findings here are live**: public API, WP-CLI entry points, JS–PHP wire constants and test seams. Verify every call path (siblings, JS, dynamic) before deleting.
- **Nothing automatic runs the bundled example's JS tests.** jest ignores `/examples/`, so a change under `src/shared/` or `src/runtime/` can break `examples/example-ai-newsletter`'s dashboard suites with every gate green. Run `npm run test:js` from that directory, with both trees installed, after such a change.

`pre-commit` syncs the shared tooling, then runs lint-staged (PHPStan included); `commit-msg` runs commitlint. `pre-push` runs `scripts/lint-docs.sh` — a grep gate holding `docs/`, `README.md`, this file and `.claude/skills` to the runtime — the JS suite with its 90% per-file gate, and the gates' self-tests on every push, then the PHP, JS or SCSS gates the push touched.

This repo holds the **authoritative copy of the shared `scripts/`**. Every sibling vendors a copy, which `scripts/sync-shared-scripts.sh` refreshes from here in each sibling's `pre-commit` whenever `../newspack-nodes` exists. Edit the copy here. `pre-push` is shared too, and fails a push without the `scripts/pre-push.local` it sources, which the sync never touches. Each plugin's `.local` declares six constants — `PLUGIN_SLUG`, `CONTAINER`, `DEPLOY_CONTAINER`, `DEPLOY_SCRIPT`, `TEST_DIR_IN_CONTAINER` and `COVERAGE_DIR` — and two slot functions: `push_gates` runs after the shared gates, and `container_gates` after the coverage suite. A gate that runs a `scripts/` file is one `script_gate` line, and pyrobase's and nuclear's date_math parity is one `date_math_parity <side>` line. The shared gates include `check-substrate-floor.sh`, which passes at once in a plugin declaring no floor. This repo's `push_gates` runs the shared tooling's self-tests, which belong here alone: the sync vendors that tooling byte for byte and no `test-*.sh`. `.shellcheckrc` rides along so shellcheck follows the hook into its `.local`. `build.mjs`, `bump-version.sh`, `get-line-at-offset.sh` and every `test-*.sh` are never synced, and `render-diagram.sh` (a `docs/img/*.html` sheet to PNG, every sheet when given none; `CHROME=` overrides the browser path) reaches only a sibling with `docs/img/`, beside the `autocrop.py` it calls.

## Versioning & Release

Change the version only through `./scripts/bump-version.sh <version>`: it rewrites the `Version:` header, `NEWSPACK_NODES_VERSION`, `package.json` and the `SUBSTRATE_VERSION` banner in `src/build-kit/index.mjs`, and syncs `package-lock.json`. Pushing a strict `v<major>.<minor>.<patch>` tag runs the Release workflow, which builds every zip through `build-release.sh`, the one definition of archive contents, and publishes. `/release-event-logger newspack-nodes <version>` is the runbook.

**A signature change raises every consumer's `version_at_least()` floor.** Change the signature outright, update every caller in the sibling plugins in the same pass, and raise each caller's floor to the release carrying the change, so a consumer meeting an older substrate goes dormant instead of fataling. No default parameter or shim keeps the old call working: a default that reads nothing is fail-silent. `scripts/check-substrate-floor.sh` measures a consumer's floor against the API it calls — a lower bound, because it drops calls PHPStan cannot pin to one class — and `docs/upgrading.md` lists the rewrite.

## Architecture Decisions

Intentional, load-bearing choices; "fixing" one usually reintroduces a bug already paid for. Each is an ADR with its context, alternatives and reopen condition in **[`docs/architecture-decisions.md`](docs/architecture-decisions.md)**. "Decision N" here and in code comments means **ADR-N**. Numbers are stable: supersede, never renumber.

| # | Decision |
|---|----------|
| 1 | Uniform `fill()` contract — one entry point per node, no `write()`/`read()`/`process()` |
| 2 | ONE message format: the 7-field positional array (`Message::*` constants; no object form) |
| 3 | Fire-and-forget messaging — no TM_PERSIST ack; the single-threaded drain is the backpressure (keep `TM_NOREPLY`); a node owning non-blocking I/O holds an in-flight window it bounds itself (`Curl` by count, `HTTP_Out` by timeout), and a stop loses it |
| 4 | PIPE_BUF atomic writes — 4 KB default; larger writes opt into `allow_large_writes()` and its lock |
| 5 | Lazy init for Topic / Partition — constructors do no event-loop or filesystem work |
| 6 | CRC32 + 31-bit-mask partition routing — `hash_to_partition()` is canonical |
| 7 | `sink` (physical) vs `target` (logical TO path); replies go TO=FROM; no `edge`; a reply head names its command session, `_sse:<handle>` for a browser and `_cli:<pid>` for a cli process, and one `HTTP_Filter_Node` per session gates on it |
| 8 | Worker zombie pattern — detached ~595 s requests; release before self-respawn |
| 9 | Two-tier safety net — worker self-respawn and the peer `_fleet` scan, then the WP-Cron cold start |
| 10 | `Word_Word` / `_Node` naming, resolved through `register_namespace` (no `class_map`) |
| 11 | `make_node` construction sequence; `arguments()` defaults and requirements centralized in `parse_schema_args()` |
| 12 | Dead-letter lifecycle — bounded retry, then `:deadletter` quarantine for caught-throw poison; crawl-checkpoint on uncatchable death |
| 13 | `fill()` returns void — outcomes come back as messages (TO=FROM reply, TM_ERROR), never a return value |
| 14 | Cooperative stop propagates — a broad `catch` on the drain path re-throws `Worker_Should_Stop` first; an attempt-all loop raises everything after the last, through `Worker_Should_Stop::combine()` |
| 15 | Command authorization — `Message::LOCAL` in process, HMAC on the wire; the MINTER signs, never the ingress; the session key chosen is the destination binding |
| 16 | JS node-class resolution — a NAME is the TSL and palette surface; a programmatic builder hands `makeNode` the CLASS, because `includeNodes` is per bundle |
| 17 | Timers fire on one shared wall-clock GRID, so harmonic intervals meet and batch |
| 18 | A Table can front a durable record (`backed_by`); Partition owns the index walk (`locate_by` / `read_many`), the app only what a line means |
| 19 | A node may DECLARE a destination it writes without routing (`extra_targets()` → `display_targets()`); presentation only, never a route; one its arguments name is declared once, in `Node::declared_targets()`, which the analyzer draws as `pair` edges for every class |
| 20 | A config default lives in CODE (`Schema::defaults()` or `config_defaults()`); a config file only overrides, and an unknown key there is reported, never thrown |
| 21 | A node may derive its children from the Vault (`Vault_Group`, rebuilt on RELOAD); static analysis expands every group through `Vault::in_group()`, except the editor's seed, and `dump_config` emits only the group |
| 22 | A worker id has one writer (`CLI::worker_id()`) and one reader (`CLI::parse_worker_id()`), held to the JS twins by `tests/fixtures/worker-ids.json`; `Spawn_Coordinator` owns the lock tree, `Worker_Base::ipc_dir()` builds the IPC tree, and nothing else globs, joins or strips either |
| 23 | A request carries no authority of its own: the MANAGE-gated mount of a worker's input Partition, or of a Table (`topologies mount_tables`, reads only), or the read-only mount a verb makes for the rest of its POST, bounded by that verb's role, is the gate, so `requests` entries declare no capability; a declared request answers `TM_STRUCT\|TM_RESPONSE` `{ verb, data }` or a `TM_ERROR`, and only a Table's `MSET`, `ADD` and `SADD` carry a structure, each declaring `'value' => 'struct'`, which every sender reads |
| 24 | A Table names its backend — memcache or APCu (volatile), SQLite (durable, one host) or wpdb (durable, shared); set members (`SADD`, `SMEMBERS`, `SSCAN`, `SMOVE`, `SREM`) are durable-only; a durable key carries no salt; command sessions live on wpdb |
| 25 | A verb's declared `args` are bound by `Command_Args::bind()` in `dispatch()`, before `$around_dispatch` — by position or `--name=value`, a `secret` by name only, defaults resolved through `default_of()`, a `variadic` tail or `--name=` repeat, `int`/`float`/`bool` typed, every mismatch refused — and the handler reads `$args` by name; a verb with no `args` key gets its raw tokens |
| 26 | `dispatch()` refuses every verb, first, against the role its schema declares (a service CI's own, a `:config` interpreter's patron's), MANAGE when undeclared and READ for the base `READ_VERBS`, through `Capabilities::require_verb()`: the current user's capability where one is logged in, the session's scope alone in a worker, where a site-signed command carries no ceiling; no handler checks a role |
| 27 | Withdrawn: a Ledger of write-once rows (2.80.0–2.82.0; removed in 2.83.0). The number stays retired |
| 28 | Withdrawn: a Ledger file per partition (2.82.0; removed in 2.83.0). The number stays retired |
| 29 | A log stamp has one writer (`Log_Discovery::stamp_for()`), one reader of a subscription (`split()`) and one of a FROM trail (`dir_from_stamp()`, `splitStamp()` its twin through `log-stamps.json`), which differ on `logs/x`; a root joins its base through `root()`, a dir resolves by direct path under the stream's guard (`dir_of()`), a glob by `dirs_matching()`, a source through the registry (`Log_Sources::entry()`), and the stream and the step reach the same resolver; nothing else parses a prefix, joins a root or scans a catalog to invert a stamp; a stamp's kind, the slot and dir its broker reader takes, has one codec (`Log_Discovery::kind_of()` / `stamp_of()`, held by `log-kinds.json`); a spoke's log on a hub is `remote/<vault_id>:<kind>`, written by `remote_for()` and read by `remote_of()` (`remoteOf()` its twin through `log-remotes.json`) |
| 30 | A read position, and a record's `segment:offset:length` breadcrumb, has one writer (`Log_Position::format()`) and one reader (`Log_Position::parse()`, narrowed by `crumb()`, null for what it cannot read, each caller stating its refusal), which also owns the seek words (`WORDS`, one word-to-sentinel table, read by `sentinel()` and `word()`); `formatPosition()`, `parsePosition()` and `parseCrumb()` are the JS twins through `log-positions.json` |
| 31 | A broker derives its readers from what its remote sends: a reader is built on first sight of a stamp a pair claims, whether the remote sends it (a stream line or `CURSORS`) or lists it (`list_logs`), as the hidden sibling `<broker>:<kind>`; static analysis claims the broker's two roots and draws one `pair` edge per pair, the console's TSL reader too (`pair-split.json`), and `MAX_READERS` caps glob claims, counting reader dirs earlier processes left; a pair naming no partition builds its reader once per fleet (ADR-33) |
| 32 | Proposed, not decided: a transport answers what it could not deliver — `HTTP_Out` would bounce a `TM_COMMAND\|TM_ERROR` to each sender of a dropped or failed batch, as the browser's `HttpOutNode` does, deleting the reader's step re-send clock |
| 33 | A line naming no partition runs once per fleet: `Core::owns( $written, $partition )` is the one ownership predicate — a source carrying `{partition}` runs in every worker, any other on p0 or where no partition is bound; every durable reader asks it of its `source_argument()` as written, and the on-demand wake map of each worker's partition, and one owning nothing idles in one state `Durable_Reader` holds (`POLLING` `IDLE`, no dirs); a broker's `Remote_Consumer` names none, its broker having asked per pair; `Durable_Reader::refuse_shared_dirs()` refuses a per-partition source beside a shared dir at load and in the analyzer; `{partition}` is the one spelling, resolved by `Schema_Reflection` in the arguments a `node_schema()` marks `'partition' => 'bound'` (`'each'` leaves it to a Topic), and the Shell refuses `<partition>` |

## Common Pitfalls

- **`@wordpress/*` is pinned exactly to the `wp-7.0` dist tag; never bump it to close an advisory.** `scripts/lint-wp-pin.mjs` fails a push when a declaration carries a range or the lock resolves elsewhere. The build externalizes these packages to `wp.*`, so a bump ships no code: it only moves the API you compile and test against ahead of the one the browser runs, and a changed component then passes every gate and breaks at runtime. Dismiss an advisory reachable only past the pin; npm `overrides` cannot scope around it, because it matches by package name across the whole tree. Move the family together, and only when the WordPress target moves (`npm view @wordpress/<pkg> dist-tags --json` against `wp core version`). Tooling packages are not pinned.
- **Five `Config_System` files stay Core-free** — `field`, `schema`, `options-overlay`, `reset-gate` and `field-reset-assets` — because pyrobase's `tests/load-config-system.php` loads them without the substrate. Never call `Core::` or another substrate class from them; `settings-renderer` and `restart-planner` may.
- **Messages are arrays, not hashes.** Index with the `Message::*` constants: `$message['type']` appends an eighth key that `packed()` drops. A TM_INFO or TM_REQUEST VALUE is a string, except a Table's `MSET`, `ADD` and `SADD` (ADR-23), and structured data takes TM_STRUCT. A multi-field one is a flat `KEY VALUE KEY VALUE` string of whitespace-free tokens, as `SSE_Out_Node::build_connected_msg()` mints it; `set_state()` follows the same rule.
- **Pick the `Core` coercion by its guard.** `as_*` cast leniently (`as_int('42')` is 42, `as_int(true)` is 1); `num_int` / `num_float` validate numerics, sending bools and `'12abc'` to the default, and belong on arithmetic paths; bare `str` / `arr` / `int` pass only the exact type, so `int()` on a JSON numeric string returns the default. An operator-supplied value wants the refusing `canonical_decimal()` instead, because every other family turns `--partition=abc` into p0: a WP-CLI flag reads through `Command_Args::option_int()` and refuses with `CLI::require_flag_int()`. A verb argument or a positional `make_node` token declares its `type` in `node_schema()` and lets the binder or `parse_schema_args()` refuse it; never hand-parse what the schema declares. Test presence with `has_value()` (Perl `length()`) wherever `'0'` is legitimate — a partition, a KEY, a count — because `if ( $s )` drops it.
- **Sources stamp FROM; forwarders don't.** A node that mints a message stamps its own name — Shell `_output/_cli:<pid>/_output`, an interpreter `$this->name`, Timer, Tail and Consumer at their boundary — even on a message expecting no reply, because a misdirected command is traced by FROM. Tee, Hook and application relays pass FROM through. Transports (`HTTP_Out`, the SSE relays, a Partition) carry all seven fields verbatim and invent no addressing (ADR-2); when a caller breaks the contract, fix the caller, never the transport.
- **A reply is already addressed — never correlate it.** The server replies TO=FROM, so the reply lands on the node that minted the command, and its `fill()` handles it. Never mint an op-id into `message[ID]`, keep a promise registry, return a Promise from a transport, or use KEY as a demux discriminator. Needing to tell N replies apart means one node is doing N jobs: split by job, never by subject, because the subject rides in the address — FROM `vault:test:in/spoke-01` echoes back to `vault:test:in` with `spoke-01` left in TO. `HTTP_Out` still batches every node's commands into one POST per tick (ADR-7), and `scripts/lint-contract.mjs` refuses the JS correlation shapes.
- **`stamp_message()` drops instead of stamping a bad FROM**: when the node has no name (mid-construction or post-rename), and when FROM would exceed `MAX_FROM_SIZE` (1024), which stops path explosion on cycles. Keep the rate-limited drop.
- **A self-pacing node holds a RECURRING timer; `oneshot` is for single wakeups.** `fire_cb()` disarms a oneshot before dispatch, so a node that re-arms one at the bottom of `fire()` leaves the loop after its first early return or throw. Call `set_timer( $next_ms )` only when the interval changes, stop explicitly with `stop_timer()`, and keep every other arming site (boot, play) recurring too. `Durable_Reader::fire()`, `Remote_Consumer_Node::fire()` and `Stdin_Node::fire()` are the models; Partition's debounce and `HTTP_Out`'s flush are the only legitimate oneshots, and the JS `TimerNode` follows the same rule. A slow drain is a cadence bug: re-arm faster rather than `while`-draining a backlog inside one `fire()`, which blocks every other node and breaks `line_mode`'s one line per cycle. A tick that paces a channel, such as `Remote_Source`'s heartbeat, is not the pump's rate.
- **Never guard a runtime invariant.** `_router` exists in every real graph, so `Timer_Node::set_timer()` throws when a hitchhike finds none. A guard for an impossible state hides the breakage. When a unit test lacks the invariant, stand the node up as a real graph does; if that means editing many tests, rethink the new coupling.
- **Never hardcode a partition's place in a path.** `{partition}` may sit anywhere in a `.tsl` path (`requests.p{partition}`, `{partition}-requests`), so a `.p{N}` literal or a `\.p\d+$` regex misses other layouts. Resolve directories through `Topology_Analyzer::resolved_resource_dirs()`, and prefer the names a live worker reports over re-deriving them from disk.
- **Only the client heartbeat refreshes an SSE slot's TTL.** `SSE_Out_Node::$check_slot` only checks; the `workers heartbeat` verb (`SSE_Slot_Pool::touch()`) refreshes. The pool is the rate limit, and a refresh on check would let an abandoned stream hold its slot forever. `SSE_Slot_Pool::ttl()` floors the TTL at 45 s, three `Remote_Source_Node::HEARTBEAT_INTERVAL`s. The browser's `_heartbeat` and `Remote_Source`'s poke are both load-bearing.
- **Release the worker lock before spawn.** `Worker_Base::execute()` runs `release()`, then `self_respawn()`. Reversed, the successor's acquire hits the held lock and skips, idling the slot until a peer rescues it.
- **Internal HMAC tokens accept two windows**, the current and previous 10-second ones. Don't tighten to one: the race tolerance is intentional. Purposes are separated in the hash, so a token for one endpoint never validates at the other.
- **Partition and Topic pack ALL message types**, TM_REQUEST, TM_ERROR and TM_EOF included, because IPC rides on them: `request_node`, `send_eof`, attached-mode errors, and the cli's drain on stdin close, where the interpreter bounces TM_EOF back TO=FROM and the cli's Dumper exits on the echo (5 s fallback). `Log` alone drops those three.
- **Skip readline when STDIN isn't a TTY.** `readline_callback_read_char()` reads the TTY layer, so piping into `wp nodes cli` without the gate burns 100% CPU. Keep the gate.
- **`Command_Interpreter_Node` only handles a TM_COMMAND with an empty TO and no TM_RESPONSE bit.** A non-empty TO means the message is in transit, so the interpreter forwards it to Router; dispatching on it would make every interpreter in a path-routed graph eat commands meant for peers downstream. The response-bit check stops a successful reply (`TM_COMMAND|TM_RESPONSE`) whose TO is already peeled from re-entering the verb table.
- **An active topology that will not read fails loud, never silently.** A name no `.tsl` resolves, or a broken include, surfaces as a critical `worker-liveness` row, an `unreadable` entry in `dump_graph`, a `wp nodes status` warning and a raise from every spawn pass, restart and retention sweep. A stale name in the `topologies` config key therefore fails every spawn pass until it is removed.
- **A refusal THROWS; a `return` is a result.** Verb handlers throw freely and `interpret()` wraps the throw as TM_COMMAND|TM_ERROR, so add no per-verb `try`/`catch`. Every refusal raises — `usage: …`, `unknown node/class/formatter`, `no such topic`, a secure-level denial — because one returned as a string is indistinguishable from success. `remove_node`'s per-name refusals, `dump_node` with no name, and `Log_Sources`' unavailable catalog rows are existing carve-outs, not shapes to copy.
- **A constructor sets `$this->arguments`.** The base `dump_config()` reads it to emit a round-trippable `make_node` line; forget it and the round trip builds a different node. State a VERB set needs an override that calls `parent::dump_config()` and appends its own `config_line()`s, as `Partition`, `Topic`, `Consumer`, `Remote_Source` and `Settings_Sync` do.
- **`Log` is a `Partition` subclass** with the same segments, rotation, retention, rotate lock and 4 KB cap. It differs three ways: it writes the message VALUE rather than the packed envelope, lays segments out as `{file}.0`, `{file}.1`, … with no bare `{file}`, and drops TM_ERROR, TM_EOF and TM_REQUEST. Args: `make_node Log <name> <file> [segment_size] [min_segments] [num_segments] [max_segments] [min_lifetime] [lifetime]`.
- **`Echo` drops a TM_ERROR with an empty TO**, which would otherwise bounce to a producer not expecting it. Keep the drop if you change Echo's routing.
- **The "Nodes" wp-admin page is the station**, and its tabs are station tabs (`src/station/`, `host: 'station'`, `newspack_nodes/station_tab_bundles`). "Hub" means the aggregating site of hub-and-spoke, "DevTools" the browser's panel, and "debug overlay" the floating panel.
