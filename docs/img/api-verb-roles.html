Who may call what: every service verb and the role it declares

Passing the door proves read, the floor. Authority is then decided per verb: each service CI declares a role in its node_schema(), and Service_CI_Node wraps the handler in Capabilities::require() at INSTALL. A verb that declares nothing demands manage, the strictest role, not the loosest.

read declared read tune declared tune manage declared manage, or declared nothing help seeded by the base at manage

Every CI answers help, which Service_CI_Node::commands() seeds gated at manage before the parent can inject an ungated one; it returns that interpreter's own verb names, sorted. No substrate CI declares it in its schema, so a caller holding read alone, the log aggregator's hub user among them, is refused help on every service CI while the base interpreter answers it at read.

The root table is pinned at manage by ensure_request_graph(), with the fifteen read-only builtins every dashboard drives excepted, because the strictest verb must not set the privilege level of every caller: the log aggregator would otherwise hold an administrator's application password to pull a read-only stream. help <NodeType> resolves the same class table as make_node. Application plugins mount further CIs on the same endpoint; TO alone distinguishes them, with no substrate-versus-application namespacing.

Gated at install, never at dispatch

commands( $table ) wraps every entry of every table handed to it for the role the concrete class's schema declares under that verb NAME, and manage for a name the schema does not declare, so a table replaced after construction is still gated at the declaration's role. Called with no argument it is a read and re-wraps nothing, so a second check never stacks.

A refusal THROWS permission denied: <role> capability required, and interpret() wraps it as TM_COMMAND|TM_ERROR. A scoped session lowers the ceiling for one command and can only subtract.

Shell builtins mint nothing, or address elsewhere

Shell_Node intercepts its own before any of the above: cd (chdir), include, var, print, clear, debug_level, status and show_parse change REPL state and mint no command; command_node, request_node, ping, tell_node, send_node, send_struct and send_eof mint a message addressed elsewhere rather than dispatching under their own name.

The secure ladder climbs and never descends

level 1disables the make_node class: make, move and remove, with their aliases
level 2adds the command_node class: reply_to
level 3adds the connect_node class: connect, disconnect, set_sink, register, unregister

It freezes definitions and never disables the machine: reads still read and wired flow still flows. A node classifies its own verbs through node_schema()['verb_classes'], so a consumer plugin joins a class without editing the substrate.
