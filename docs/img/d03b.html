A reader's four states

A Consumer reads one Partition and keeps its place in a second. A message that fails moves it to the right; a process that dies moves it down. Both roads lead back to reading.

Reading clean

The Consumer is a timer node reading one Partition. Each tick reads at most one 64 KB block from the cursor, unpacks each line into a message, stamps its own name into FROM and its target into TO, and fills its sink.

The cursor, a segment and a byte offset such as 2:48120, names the next unread record. Caught up, it wakes ten times a second.

Every thirty seconds, and at a clean shutdown, it checkpoints the cursor to the offsetlog. A clean shutdown stamps the attempt count to zero.

Quarantine poison

The message goes to the dead-letter Partition and the stream keeps moving. A line that will not unpack goes the same way with its raw bytes kept.

There is no automatic retry, because a throw is deterministic per message. Dropping it would lose data; retrying it forever would wedge the stream. The operator fixes the cause and replays.

Boot crash

A crash leaves no throw, so the attempt count carries the evidence. A restart reads the newest offsetlog entry and resumes at the stored count plus one, so a crash costs at most thirty seconds of re-delivery and never a gap.

Only a stuck cursor climbs: four boots that each die on the same record leave a count of four and no reason.

Crawl crawl

The reader quarantines the message it resumes on with the reason crash, then checkpoints after every message, so the next crash pins the culprit.

Thirty crash-free seconds end the crawl and the reader returns to a checkpoint every thirty seconds.

offsets/<topology>.firehose.p0/

The offsetlog: a second Partition, named by the Consumer's second argument. Each entry holds the segment, the offset, the attempt count and the last stop reason.

It rotates at one byte and keeps ten to sixty segments, so every checkpoint is its own segment and the dashboard's time-travel debugger can seek to any of them.

deadletter/…

The dead-letter queue: a third Partition, named by the Consumer's third argument. It keeps sixteen segments by count and never by age; a record that sits all weekend is the one an operator comes back for. wp nodes ingest replays it.

The write side quarantines here too: a short write or a failed segment open sends the unwritten records, replayable but not requeued.

A shared log: step off a segment slowly

A peer may still be appending to segment N for a second after N+1 appears. A reader told the log is shared, as the event logger's firehose is, steps off N only after N's size has held steady for two seconds.
