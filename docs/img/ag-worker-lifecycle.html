A worker is an HTTP request that outlives its caller

Seven hops from the spawn POST into the drain loop. The endpoint is the one gate every spawner crosses, the lock directory is the slot, and should_continue() is the only thing that beats the lock. The handoff that follows is its own diagram.

Spawner

A predecessor's self_respawn(), a peer's _fleet scan, the cron pass, an activate, or a wake.

Spawn endpoint

POST /newspack-nodes/v1/workers/spawn, Spawn_Controller.

Worker_Base

execute( $topology, $spawn_url, $token ) inside that same request.

Lock dir

{base}/locks/{type}.p{N}.lock.d/ — the slot.

1Core::fire_and_forget_post() hangs up after SPAWN_POST_TIMEOUT_MS 250. Auth is an HMAC token over a 10-second window (current or previous accepted), purpose spawn; or a MANAGE user with a WP nonce, behind RATE_LIMIT_S 2 per user.
2Three refusals in order: a partition outside the type's range → 400; a deploy hold (newspack_nodes_hold option) → 409; spawned less than MIN_SPAWN_INTERVAL_S 15 ago for this {type}|{partition} → 429. The accepted spawn is recorded here, shared through Cache_Backend::shared_first(), so N scanners are as safe as one. Then ignore_user_abort( true ) and set_time_limit( 0 ): the caller is gone, the process stays.
3Worker_Base::execute() runs inside this request for the worker's whole life and writes its WP_REST_Response only once the graph is torn down. Nothing detaches from FPM or the process group: the process holding the spawn connection IS the worker. fastcgi_finish_request() is deliberately absent (ADR-8), since no caller waits for the reply.
4acquire() the lock; on refusal return skipped with acquire_failure(). Register the shutdown handler, then usleep( LOCK_CHECK_GRACE_S ) 250 ms, so a spawn racing this one reads the lock as held.
5build_scaffolding() mounts _router (ticking at 1000 ms), _command_interpreter, _fleet, the _repl output Partition under void_warranty(), and the anonymous IPC-input Consumer stamping _repl.
6run_topology() evaluates the .tsl. A file that throws — an include cycle, input pending at EOF — logs, releases, returns load_failed and does NOT respawn. A bad single line is caught per statement and the worker still reports ok.
7drain( should_continue, cooperative_stop: true ) — for about 595 seconds
baseline_memory = memory_get_usage( true ), then install_signal_handlers(): only Worker_Base::execute() and ELN's Reqgrep_Command::follow_mode() ever install them.
The predicate runs on every tick and from pump() at most once a second, in this order, and it is the only thing that beats the lock:
1 · the lock is no longer ours, or its dir is gone
2 · stop_requested() — category stop, before restart, because a stop leaves the slot EMPTY
3 · restart_reason() non-empty: the flag, a gone heartbeat, a stolen lock
4 · DEFAULT_MAX_RUNTIME 595 s reached — timeout
5 · memory ≥ MEMORY_WATERMARK_PCT 0.80 of memory_limit — memory; PHP's fatal-on-OOM would bypass finally
6 · the DB probe failed DB_CHECK_MAX_FAILURES 3 times running
7 · every Idle_Reporter idle for the whole on-demand window — idle; skipped under $mid_work
Three branches are throttled inside it: the heartbeat touch every HEARTBEAT_INTERVAL_S 10, the DB probe every DB_CHECK_INTERVAL_S 30, the idle scan every IDLE_CHECK_INTERVAL_S 1, because it lists segments and stats the newest, and per-tick disk I/O would cost more than the residency it gives back. A process that asks whether to keep running also proves it is alive.
