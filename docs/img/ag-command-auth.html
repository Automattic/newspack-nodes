Every command passes two gates: the signature says who minted it, the capability map says whether they may

One Command_Interpreter_Node class runs in two trust roles, so the first gate is a per-instance authorize closure checked in interpret() for every command. The second is Capabilities::require() around every service verb. Authenticity and authority are two questions.

Client tier — the browser interpreter, the bare wp nodes cli

Commands are minted in-process by a Shell_Node, which sets Message::LOCAL at index 7. The default authorize is one test:

isset( $message[ Message::LOCAL ] )

packed() and pack() slice to LAST_VALUE_INDEX + 1, so LOCAL is dropped at every wire and IPC boundary — HTTP POST, SSE, the Partition IPC, the HTTP_In echo. An injected off-process command inherently lacks it.

Server tier — worker CIs, the /command request-scope CI, the SSE-stream process CI: Command_Auth::verifier()

A LOCAL command passes at once. Anything else must carry a valid HMAC envelope in VALUE['auth'] — inside VALUE, so it survives the IPC that strips LOCAL:

1
Is it a command? Decided by the TYPE bit: TM_COMMAND set, neither TM_RESPONSE nor TM_ERROR, a numeric TIMESTAMP, an array VALUE. Never by sniffing a name key. TYPE gates signability and is not in the signature, so TM_COMMAND | TM_NOREPLY signs like any other.
2
Freshness: at most MAX_PAST_S 20 s old, MAX_FUTURE_S 10 s ahead — an age check, distinct from the spawn token's discrete 10-second windows.
3
Resolve the key. A handle in the envelope names a session: the key comes from Cache_Backend::shared_first(). No handle: the per-site secret, hash_hmac( 'sha256', 'nodes-command-v1', wp_salt( 'nonce' ) ).
4
Recompute the HMAC over the canonical string JSON.stringify([ ts, name, arguments, nonce ]) — semantics, never routing, because the Router peels TO and nodes stamp FROM in transit. PHP encodes with JSON_UNESCAPED_SLASHES | JSON_UNESCAPED_UNICODE to match JS byte for byte; tests/fixtures/signatures.json pins the parity.
5
Single use: the nonce is claimed with an atomic add() through Cache_Backend::local_first() at NONCE_TTL_S 60. A replay, or an unavailable backend, is refused.
Any failureverify() logs verification failed: … through the HANDLING interpreter's drop_message, installs scope NONE, and returns false. The reply is unauthorized: <verb>; HTTP_In latches it and the whole batch answers 401.
Passthe session's scope becomes Capabilities::$session_scope for this one command; interpret() restores what stood before.
Gate 2 — Capabilities::require( $role ), wrapped around every Service_CI_Node handler
readdashboards, the SSE streams, read-only introspection. Its live surface is the RAW log firehose and worker IPC output, not shaped dashboards alone.
tunedeclared configuration and application data: settings, the ELN ruleset.
managefleet control, the credential vault, issuing sessions. A verb naming NO role in node_schema() gets this one — the strictest, never the loosest.
Resolutioneach role → a WordPress capability through the newspack_nodes/capability_map filter, all three manage_options until wp nodes caps install migrates them onto newspack_nodes_{read,tune,manage}. The autoloaded newspack_nodes_granular_caps option is the switch.
The ceiling only subtracts$session_scope lowers the ceiling for one command and can never buy authority the authenticated user lacks. Roles::install() grants all three to every role holding manage_options and creates newspack_nodes_hub — read plus tune — for the aggregator's user.
Refusalpermission denied: <role> capability required; the batch still answers 200, because the signature passed.

Two signing keys, and the choice is the destination binding

Command_Auth::sign() uses the per-site secret and stamps no handle: the attached cli's Shell signs this way inline, same host, over the IPC partition.

sign_for( $destination ) signs under the session key established with one remote and stamps its handle. A signature under one remote's key verifies only there, which pins a command to its destination without signing TO. No session means no signature: a minter waits rather than emitting something that will rot.

Sessions live in a private static map, per PROCESS and keyed by VAULT ENTRY ID, never by url: two entries on one host stay two sessions, and editing an entry's url keeps its session. HTTP_Out_Node establishes one — ensure_session() async, establish_session() blocking for probe_command() — landing in remember_session(). Three things drop one: a 401 from the spoke, process exit, a Vault change. A POST /auth in a spoke's log every ten minutes is a worker recycle, by design.

POST /newspack-nodes/v1/auth mints the session — the minter signs, never the ingress

Gated on the fleet site, then the READ role: a scope is a ceiling, so a read-only user's session can only do read-only things. Returns { handle, secret, scope, expires_in, now }: a random 16-byte handle, a random 32-byte key, stored with add() — never set(), so a colliding handle fails rather than displacing a live session. scope is clamped to the minting user's highest role; ttl to SESSION_TTL_MIN_S 60 … SESSION_TTL_MAX_S 86400, default SESSION_TTL_S 3600, and never slid on use, so a leaked handle expires on a bounded schedule. The response is the only place the key is ever disclosed; now lets the client align its TIMESTAMP.

Sessions is the durable directory beside the cache: a non-autoloaded option, one row per LABELLED handle, never the key. The automatic dashboard mints, several per page load, stay unlisted, because at MAX_ROWS 50 they would evict the sessions an operator issued. The cache stays the authority on liveness, so a row whose lease is gone reads dead rather than vanishing.

HTTP_In decodes, routes and verifies. Conferring authority at the ingress would make the boundary an oracle: anything that reached it would acquire authority, whatever put it there. Every tier is HMAC-SHA256; there is no asymmetric signing anywhere.
