One entry point, and an ownership boundary in both directions

Every node is reached through fill( array $message ): void and nothing else. The message is handed over BY VALUE, so the caller keeps nothing; and fill() returns nothing, so the caller learns nothing. Nodes compose because no node can reach back through a fill() call.

Forward: by value, never fill( array &$message )
Tee::fill( $m )hands a copy to each of N →target 1 edits its copytarget 2 sees the original
by referencethe same array to all N →target 1's edits leak into target 2; the caller's FROM and ID are clobbered before it reads them for the reply

PHP copy-on-write makes the copy free until someone writes. A message handed to your fill() is yours: mutate freely, the caller never sees it. A message you forwarded belongs to the downstream: hold no reference, expect nothing preserved.

The JS runtime keeps the discipline without the language behind it. Node.fill() hands its sink the SAME array; TeeNode and TapNode slice() once per branch at fan-out, the case the rule exists for. That copy is SHALLOW: a TM_STRUCT VALUE is one object shared by every branch, so a struct is immutable past a Tee or a Tap and a downstream that must edit one clones it first. CallbackNode is terminal and hands the closure the caller's own array, so a closure that writes into the message edits what the sender still holds.

Return: void, never a disposition (ADR-13)
nodefill() →sinkoutcome comes back as a MESSAGE →TO=FROM reply, TM_ERROR, or a send to a target
$result = $sink->fill( $m )→the caller depends on the downstream's disposition: delivered, dropped, queued, transformed

If a node could read what its fill() returned it would couple to the downstream, and swapping that downstream would change the caller: the callee-coupling the uniform contract removes. A Tee filling N targets has no single disposition to hand back, and flow control is the single-threaded drain (ADR-3), not a return code.

This covers ANY value: a parse, a validation, a lookup the node computed before its sink was touched is still a return, and still couples the caller to this node's internals. PHP enforces : void; JS keeps it by convention, a bare return; for early exit only. Perl Tachikoma's fill returns values only because Perl has no void; nothing downstream reads them.

Rejected: per-node typed methods

enqueue(), publish(), handle(), or write() beside process(): callers special-case, and a node can no longer be swapped without touching them. Testing any node is "construct a message, call fill(), inspect the sink."

Rejected, and it arrives disguised as cleanup: exposing fill()'s stages

A parse() that returns the parsed result and a dispatch() that sends it is the same parallel API with the pieces renamed, and worse than one process(): the caller now knows this node has two stages and their order. It drags ADR-13 down with it, since the stage a caller reaches for hands its result back as a return value. Helpers are fine as fill()'s own internals; nothing outside calls them to get a message in.

The wrap rule

A node whose natural input is not a Message — a typed REPL line, a raw wire frame, a file chunk — does not widen its signature. The producer wraps: a line arrives as a TM_BYTESTREAM whose VALUE is the line, and Shell_Node::fill() reads the statement out of the VALUE. Richer control surfaces are message types and verbs through an interpreter, never new methods. Neither decision has met a case it could not absorb.
