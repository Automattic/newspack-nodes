The browser runs one graph per page, and each Router tick leaves as one POST

Every consumer bundle inlines its own copy of the runtime, so the one Core parks on window.__newspackNodesCore and every bundle's nodes share its name table. The Router starts its own 1000 ms slot and brackets each tick between HttpOut's lock and flush, so every poll due that tick batches into one /command POST.

Twenty seconds of a console with 1,000 nodes on screen

computePollIntervalMs() rounds nodes × 10 ms to the nearest five seconds and floors it at five, so every metadata cadence is a multiple of the uptime one. Every poller rides the Router's TIMER channel on the one shared wall-clock grid (ADR-17), which is why harmonic cadences meet on the same tick and leave in the same request. The _dmesg poll is aimed at _cwd, so it tallies the stderr tail of the process being VIEWED.

The JS Router has no drain loop, so its constructor self-starts the slot with setTimer( ROUTER_TICK_MS ); a test that wants it quiet calls stopTimer(). Only mountExospine mounts _http, as an HttpOut, so a dashboard that never heard of the bracket still batches. The PHP Router wraps nothing in a finally: there, a throwing hitchhiker ends the worker.

The browser SSE receive path delivers TM_RESPONSEs to _output, _metadata and _uptime. Parking Core on window is what lets the debug overlay mount its _output and _metadata into the registry a dashboard already built.

A stale WordPress nonce

A REST error coded rest_cookie_invalid_nonce makes commandTransport call renewNonce (refreshNodesNonce), which refreshes the X-WP-Nonce WordPress checks before HTTP_In sees the body. It then invalidates the command-signing session the old nonce derived and retries the same POST exactly once. A second failure is reported, not retried.

A refused signature: HTTP 401

renewSession() drops the local signing session and opens a doubling backoff window, BACKOFF_START_MS 1000 up to BACKOFF_MAX_MS 30 s, before the next command may mint. Without it a session the server keeps refusing spins at the poll cadence.

The browser signs synchronously

With @noble/hashes rather than crypto.subtle: awaiting a promise would make the Shell's dispatch async and move every graph mutation a microtask later. useNodeFill( name ) resolves its node at CALL time and discards the message while no node holds the name, since a UI handler can fire before its graph exists.
