One tree, one host

Every path the runtime writes hangs off a single base directory. Nothing in it crosses a machine boundary, and nothing in it is shared with another install.

The runtime base directory  ·  /tmp/newspack-nodes by default, set on the Nodes Runtime settings page, and printed resolved by wp nodes doctor
├─ logs/
Every Partition, as a flat directory per partition. A Topic with N partitions leaves N of them side by side.
│  ├─ firehose.p0/  0.log 1.log 2.log
The event logger's firehose, partition 0. The numbered segments are the log; appends land in the highest.
│  └─ digest.md.0  digest.md.1
A Log: a Partition that writes the message's VALUE verbatim, with no envelope and no added newline, so a pager opens the file. Its segments sit beside the named file and the bare name is never written. A Tail reads a Log back as raw lines.
├─ offsets/
Every offsetlog, named for the topology, the log and the partition, as <topology>.firehose.p0. Two topologies tailing one log keep separate cursors.
├─ deadletter/
Every quarantine. A write-side one is named for its source directory with the slashes turned to dots.
├─ locks/   ├─ ipc/   └─ topologies/
Worker locks, the console's input and output logs, and the topology files. Part 4 opens these three.

A Partition writes a record

TYPE TIMESTAMP FROM TO ID KEY VALUE↵

All seven fields, packed into one line and terminated. A Consumer unpacks the line back into a message, so the envelope survives the disk.

same class,
one override

A Log writes the bytes

VALUE

The payload and nothing else. The reader of a Log is a person or another program, so it drops the three control types, which carry no payload worth a line.

The whole tree is one host's private state

No record in it is replicated, and no reader on another machine opens it. That is what buys the lockless append, and it is the boundary part 7 crosses with a pull rather than a shared mount.
