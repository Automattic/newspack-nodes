At _routerevery drop is a rate-limited stderr line
WARNING: message not addressed
TO is empty: the minter stamped no target and nothing filled TO on the way in. Give the node a target, or sink it straight into the receiver.
WARNING: path exceeded 1024 bytes
A routing cycle grew FROM past MAX_FROM_SIZE.
WARNING: breaking recursion
A NOT_AVAILABLE bounce whose own return path is missing too.
NOT_AVAILABLE
The HEAD segment resolved, the Router peeled it, and a later segment names nothing. A Tee keeps such a target alive: spoke/settings lives as long as spoke does. Fix the topology, or disconnect_node <tee> <target>.
At a Tee or a filterread ls -c; the counter counts what a node FORWARDED
ls -c: the Tee's counter climbs, every downstream counter holds still
live_targets() prunes dead entries on every read, so a Tee heals on its next message; once the last one goes the Tee is a terminus. It forwards no original, the loop runs zero times, Router never sees the message, nothing bounces. ls -t <tee> or dump_node <tee> shows what survived; re-connect_node the branch.
fill requires a wired sink
The loud sibling: fill() calls require_sink() before it reads the target list, so a Tee with no sink throws on its first message.
ls -c: a Grep or Age_Sieve sits at 0 while traffic reaches it
++$this->counter lives inside Node::fill(); a miss returns before it. The node may be seeing every message and matching none. Tap the edge with a Tee before calling the upstream dead.
Into the Partitionmeasured on PACKED bytes, batched to the tick
WARNING: oversize: <n> > 4096
Over the cap in force, dropped whole: half a record desyncs every reader after it. allow_large_writes() (a held write lock) or void_warranty() (the caller asserts single-writer) lifts it to 32 MiB.
the reader polls and sees nothing new
The batch has not flushed. set_timer( 0, true ) drains it at the end of the current event-loop iteration, so a synchronous write-then-read with no tick between always comes up empty. ls -la the segment's mtime and size.
DEAD-LETTER [write stalled]
DEAD-LETTER [segment open failed]
Full disk. The partial record is truncated off the segment and every message the batch did not land is quarantined into the Partition's own {base}/deadletter/{dotted-path}/. dl_requeue refuses those: a Partition's sink is _command_interpreter, where redelivering an unwritten record would lose it, so replay with wp nodes ingest once there is room.
Out of the loga reader loses data the way a writer can
DEAD-LETTER [throw]
Plugin files replaced under a live worker: its autoloader fails mid-swap, forward_line() catches the \Throwable, quarantines the record and advances. restart boots a successor into the same half-swapped dir; wp nodes stop && ./deploy.sh && wp nodes start instead: stop blocks until every lock dir is gone and exits non-zero otherwise, so the deploy never meets a live process.
dump_node or trace: state OVERFLOW
A producer stopped mid-line. The partial-line buffer grew past MAX_LINE_BUFFER_SIZE, 32 MiB; the partial is discarded, the cursor skips those bytes, and a stderr line names segment, offset and limit. The bytes are gone either way; chase the producer.
At Job_Workerthe last hop, and the quietest
jobs.p{N} holds the entry; nothing runs, nothing logs
Job_Worker_Node::fill() drops silently on a handler it does not own — both kinds, deliberately, since every hub-destined job reaches a spoke's worker as an unownable k='job', and a warning apiece would flood for work the hub completes — so a handler registered only on newspack_nodes/remote_job_handlers is invisible on every spoke and a typo'd name produces nothing — and on a non-TM_STRUCT, a non-array VALUE or an unknown k. Only two drops speak, both rate-limited: over MAX_JOB_SIZE (dropped, never dead-lettered, so outside ADR-12), and a name failing HANDLER_NAME_PATTERN. request_node job-worker GET_HEALTH reports local_handler_count and remote_handler_count.
