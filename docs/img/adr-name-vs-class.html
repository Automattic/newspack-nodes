In the browser a name resolves inside one bundle, so a hook hands makeNode the class

CommandInterpreterNode.includeNodes is a per-bundle static: a flat name→class table each bundle extends at import time with registerNodeClasses(), an Object.assign that replaces a name already there with no warning. Two bundles on one page hold two copies. ADR-10 refuses a class map on the PHP side; this is the JS side's consequence of having one.

Bundle A: the station backbone
Its includeNodes after import:
TeeTimerFetcherHttpOut… the runtime's ownJobstatsView
A tab from bundle B mounts against this backbone and asks its interpreter for makeNode( 'ClassCatalogView' ): unknown class: ClassCatalogView — at runtime, in the browser, with every test green, because a test loads exactly one bundle.
Bundle B: the topology console
Its own copy of the table:
TeeTimerFetcherHttpOut…ClassCatalogView
Registering Tee here would silently replace the runtime's Tee for every later make_node Tee in this bundle: treat the builtin keys as reserved. Registration stays required for TSL and the palette, where the graph is authored as text and the interpreter reading it is the one whose bundle registered the class.

The decision: a NAME is for the text path, a CLASS is the API

makeNode( type, name, args ) accepts either; 'function' === typeof type selects the class directly and skips resolution. A programmatic builder imports the class. Three conforming shapes: a bundle whose views are written out registers a map and exports it; one whose views are declared as slices lets registerSliceViews() build, register and return them; and one whose views each have a module imports them from those modules, its register.js exporting nothing, which is examples/example-ai-newsletter's shape. What is forbidden is the NAME, never a particular import path.

const OWN_CLASSES = { JobstatsView: JobstatsViewNode };
CommandInterpreterNode.registerNodeClasses( OWN_CLASSES );
export const views = { ...OWN_CLASSES, ...registerSliceViews( { /* … */ } ) };

Enforced by scripts/lint-contract.mjs

name-lookup-in-hook catches a name passed to makeNode; name-lookup-in-option catches the same break one hop out, in a hook option's viewClass / viewType / nodeClass. Both match a quoted string literal, so a class handed in trips neither, and both read their builtin allow-list from includeNodes's own declaration, since the runtime's classes ship in every bundle. With no substrate in reach — no src/runtime, no sibling ../newspack-nodes, no .newspack-nodes clone — both stand down behind a one-line console.warn while the other six rules keep running; that is the standing state for pyrobase, nuclear-gyrobase and cache-cozy.

A dead view class is then a normal unused-export finding, and a hook that still passes a name fails the gate rather than the browser.

Rejected: a window-global registry

As src/shared/tabs/tabRegistry.js uses for tabs. It makes every bundle's node classes globally visible and collides on name, the ambiguity the per-bundle static avoids. A station tab is meant to be reachable across bundles; a view class is not.

Rejected: every bundle registers every class

Couples each plugin's build to the union of all of them, and the failure is still silent until the missing one is asked for.

Rejected: lazy resolution across a chain of interpreters

Re-invents dynamic scope and picks arbitrarily between two bundles that both registered the name. Revisit if the runtime gains one cross-bundle registry with collision handling.
