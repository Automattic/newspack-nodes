Two planes, because each carries a property the other cannot

sink is a node reference: the physical next hop fill() forwards to. target is a string path stamped into TO when TO is empty, which _router resolves one segment at a time. Replies set TO to the request's FROM and need no table.

Physical: sink
nodefill() forwards to →sink

An object reference, so it cannot leave the process and cannot be named. A node reachable only by sink is unaddressable: absent from the registry, no TO path reaches it.

The stdin reader and Shell_Node (wp nodes cli, and the JS Shell) are deliberately unnamed. The Shell is the privilege point (it marks commands LOCAL and signs them); a crafted TM_BYTESTREAM that could route TO a Shell would turn unsigned bytes into authorized commands. Shell_Node::name() throws on any argument. The only way in is the physical input path: stdin feeds the Shell, and the Shell feeds the interpreter. No name, no attack surface.

Logical: target and TO
nodestamps target into an empty TO →_command_interpreter
→_routerpeels the head segment →named node… until TO is empty

A TO path is a serializable address: it rides inside the message across IPC partitions, SSE, HTTP and the browser, where a reference cannot. cd'ing into a worker and the _output/<pid> cross-process replies depend on it. Tachikoma's pivot_client re-sinks the Shell into a socket and removes the local interpreter; here nothing rewires, only the address changes.

Targets resolve at fill time, so construction order and cycles are free. In practice targets route everything, data included: every node sinks into _command_interpreter → _router, one chokepoint for NOT_AVAILABLE and the routing counter, and the router hop is paid on the hot path.

Tee sets TO per target — the target alone, or target/TO so the remainder routes on after the peel. Echo prepends when both are set, bounces TO=FROM when both are empty, and drops a TM_ERROR whose TO is empty.

All-logical routing loses unaddressability

Every node must hold an address to receive anything, so the Shell becomes reachable by path and security by construction becomes security by checks.

All-physical routing loses the serializable address

No cd into a remote worker, no cross-process TO=FROM reply, and a rewire on every pivot. A single combined "next" pointer falls to this argument, and no port has one.

Both are load-bearing, so the split is minimal, not redundant

A subject rides in the address too: a minter serving N rows asks as vault:test:in/spoke-01, the echo peels vault:test:in and the reply arrives carrying spoke-01. Split by JOB (a verb, a poll, a stream), never by subject. A subject past SUBJECT_MAX (128) goes out with none.

Inbound at a wire boundary: what PHP's HTTP_Out does with what the remote sends back

A reply self-routes by the TO the remote echoed off our FROM breadcrumb, so anything addressed is the remote naming a node inside our graph, and every node sinks into _router, so whatever it names would be reached. The list is therefore the whole gate, and the remote sets the type bits, so keying off them would let a spoke pick its arm. Unaddressed output — a server-side log broadcast, minted with no TO and packed verbatim into the reply body — belongs to the target: that is how it reaches the browser transcript instead of dying at _router as message not addressed.

The browser's HttpOut keeps Tachikoma's type-bit test instead: a TM_RESPONSE or TM_ERROR carrying a TO self-routes, an addressed non-reply is refused while a target is set, and no allowlist applies, because its remote is the server the session is logged into and every address coming back is a breadcrumb the browser minted.

Remote_Link_Node builds a Null_Node as <name>:null, points HTTP_Out at it on every rename, and lists its own name so its heartbeat replies reach it; a Null swallows the remote's unaddressed output and counts it, where aiming the target at the relay that owns the egress would send the spoke's output straight back out. The per-spoke HTTP_Out an operator wires for topologies/settings-sync.tsl needs both lines by hand: connect_node <egress> null and cmd <egress>:config allow_replies_to settings-sync. SSE_In carries no such gate, because a subscription's records are not replies: RemoteLink sets homeToTarget and re-homes every non-command record, RemoteIpc sets it false, and a command reply keeps the TO the server addressed to its minter either way, because overwriting it would deliver the reply to the subscription's view instead of its receiver.
