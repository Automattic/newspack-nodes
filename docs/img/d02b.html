Four lines of TSL build a worker, and one record walks the graph they leave behind

A topology is a script of the same verbs the console accepts. At boot a shell, the node that turns each line of text into a command, feeds the file into the worker's command interpreter. The graph those commands leave behind is the worker.

topologies/topic-probe.tsl · the smallest shipped topology, the whole file
1
make_node Topic_Probe topicprobe 15
Builds a Topic_Probe named topicprobe with the argument 15: a timed node that every fifteen seconds records the progress of each reader in this worker. Its sink, the node object it hands every message to, is set to _command_interpreter. No line says so; every node a topology builds gets that same physical next hop.
2
make_node Partition topicprobe:log <config:logs_dir>/topicprobe.p0 1048576 2 8 0 86400 86400
Builds a Partition named topicprobe:log, which appends each message it receives to a segmented log on disk. The shell fills the <config:logs_dir> token in from the settings; the numbers size and retire the segments.
3
connect_node topicprobe topicprobe:log
Sets the probe's target to the path topicprobe:log. It hands nothing to the partition. The target goes into TO when TO is empty, and delivery happens two hops later, below.
