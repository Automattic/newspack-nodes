One spoke and the hub: the life of one connection

The hub is the HTTPS client in both directions. Its Remote_Source for the spoke bend owns two hidden nodes: :sse-in holds the long stream open, and :http-out posts one signed batch per tick. The hops are numbered in order.

Connect · the 24 sources start one every half second, so no spoke answers a burst with refusals
First tick: builds and owns :sse-in, :http-out and :null, named after itself.
1reads the entry keyed bend, the short id the source names as its first argument: an HTTPS URL, a username and a password. The password is sealed with libsodium under the site's auth salt and opened only here, on the way out.
2GET /messages/stream, with HTTP Basic auth: the hub user's WordPress application password, on this and every request.
3the handshake event names the slot leased to this stream, one of a limited set.
Stream · one long HTTP response, one server-sent event per record
and on to the source. Each record's ID is its segment, byte offset and length in the spoke's own log.
4one record per event.
Checkpoints that ID to its offsetlog and resumes from it on every reconnect. A record that will not parse is quarantined at that position, in the dead-letter partition.
5POST /auth, once, before the first batch of commands.
6a command session: a handle and a key. The hub holds both under the spoke's Vault id, and the node that mints a command signs it under the key of the spoke it is bound for.
7POST /command, one per tick. A heartbeat signed under this key every 15 s keeps the slot lease; set and get commands ride the same batch. Commands queued before the session exists are held.
8the reply, in the same response. The spoke writes every field of it, TO included. A 401 makes the hub forget the session.
Reply gate, allow_replies_to. The router delivers whatever TO names, so every outbound node carries an allowlist. A TO on the list, matched as a whole path, is delivered: this source lists its own name, so heartbeat replies reach it. Any other TO is dropped. An empty TO goes to :null.
Pressure and loss
More than 512 KB buffered on the hub: :sse-in stops reading the socket, and the spoke blocks on write. Reading resumes under 256 KB.
945 s of silence is a dead stream. :sse-in reconnects after a delay that doubles from 1 s to 30 s, and hop 4 resumes from the offsetlog.
