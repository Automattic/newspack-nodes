Seven slots, two renamed and one moved; a different bit set; JSON instead of pack

Tachikoma's Message.pm beside ours, slot for slot and bit for bit. Renaming STREAM and PAYLOAD and moving TIMESTAMP is the whole divergence budget for the layout; anything further has to be justified on its own.

The slots

The type flags: six agree in name and value, five bit values differ, six flags are absent, two are ours

PERSIST, STORABLE, COMPLETION, BATCH, KILLME and HEARTBEAT are absent here; STRUCT and UNTYPED are ours. Packing what remains into the low bits keeps a composite readable, and nothing is lost by it: the wire below was never interchangeable between the two runtimes, so a shared numbering would buy nothing.

The wire shape is the memory shape in two languages. TM_STRUCT marks an array VALUE and needs no thaw, because JSON decoding already produced one. LOCAL is never emitted and unpacked() rejects an eight-element line, which is what makes its presence worth trusting. The ports part company on malformed input: PHP throws, while JS hands back a fresh message for bad JSON and keeps the first seven fields of a longer list, so a reader off disk can quarantine the line.

Why KEY and VALUE

The vocabulary a reader already has from Kafka's ProducerRecord<K,V>, SQS message attributes and Redis Streams' XADD key value, and KEY is what hash_to_partition() routes on, which STREAM does not describe. Timer_Node follows the rename: it stamps KEY where Nodes/Timer.pm stamps STREAM.

Why the eighth slot changed kind

LOCAL is a provenance taint a Shell sets on a command it minted in-process; every interpreter admits a command carrying it and otherwise verifies or refuses. It cannot cross a process boundary, and that is the whole point. Upstream's IS_UNTHAWED exists for a Storable that has no JavaScript peer.

Why TM_UNTYPED

No upstream counterpart. It is the mint default and a free high bit, so it matches no type gate: an untyped message is inert rather than every type at once, and one that reaches a sink still carrying it is a bug the drop audit names. Message.pm's new starts TYPE at 0 instead.
