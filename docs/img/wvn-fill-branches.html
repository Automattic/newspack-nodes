setState( 'view', model )Every control, every error and every parsed reply publishes here; useNodeState( '<subject>:view', 'view' ) reads it. setState caches the latest payload, so a widget that mounts after the reply still gets the current model — a late register() replays the cache — and the constructor seeds it from emptySlice() so a render before the first reply is valid.

Preserve the order if you override

Origin first, then TYPE. Sniffing a payload for a control swallows whole streams; testing TM_ERROR after the shape check would drop a bare-string refusal as garbage, leaving any spinner running and no error on screen.
Garbage keeps the prior slice. _parse reports what it cannot use by returning null, never by throwing; if you decode anything yourself, wrap it the same way.
Recovery without a reload. The next parsed reply rebuilds from settled, which carries no error, so the card draws its data again on that tick.

The one-shot mirror

A slice keeps the model it holds when a tick fails. CommandResultNode, which useCommandOnce builds, does the opposite: every reply publishes on result, refusals included, with the same seven fields either way — ok, args, subject, payload, error, errorData, undelivered — so a caller reads ok to branch and never waits on news that already arrived.
Read them differently, too: a widget renders a slice through useNodeState, but anything acting once per one-shot answer registers a listener, because two replies inside one React batch cost one re-render and the rendered state shows only the last.
