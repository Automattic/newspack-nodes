One catalog feeds the palette and the inspector, so a category is a two-surface decision

Classes_CI drops a class from the catalog on any of three conditions, and a dropped class loses its inspector verbs along with its tile. The palette filters the same array once more on its own, which is what keeps a mounted Service CI off the canvas and its buttons on the panel.

The browser's second catalog
Where make_node runs in the browser — the console's local scope outside edit mode, the overlay's Inspector tab with no cwd — useJsCatalog() builds the same entries from includeNodes, with the same three drops and the same sort.
Read once at first render. A class the classmap finds but nothing passes to registerNodeClasses() is in one catalog and missing from the other; nothing logs it.

What to declare

A tile and inspector verbs — a normal transform or source: category: 'Transform', 'Source', …
No tile, verbs kept — a mounted Service CI: category: 'Service'. 'Remote' sits beside it under the same rule; no class declares it, so it records the principle rather than refusing anything.
Gone from both — spine plumbing with no user verbs: 'Hidden', or omit the schema. When a CI shows no buttons, this is the first thing to check: 'Hidden' where 'Service' was meant.

The per-verb flags, one level down

hidden — the verb keeps working; the Inspector renders no button and the topology editor no checkbox. The stronger flag: withheld from every surface.
multiple — the editor allows more than one invocation, one row each.
action — the editor omits it. Ticking a verb writes a command_node line into the .tsl, run on every worker boot forever; a persisted purge would discard every in-flight request on each restart. A malformed entry is skipped, never thrown, so one bad class cannot fatal the dump.
