A short name walks the registered namespaces, and the first hit is cached for life

No central registry: a plugin calls Command_Interpreter_Node::register_namespace( 'My_Prefix\' ) once, and make_node( $type ) constructs the first concrete {$prefix}{$type}_Node. The shell name is the class minus _Node: Tee_Node is Tee.

resolve_class( 'Summarizer' )

0 · the memoself::$resolve_cache[ $type ] set? Return it. Successes are always cached, misses never.
→
1 · Newspack_Nodes\registered at boot. Newspack_Nodes\Summarizer_Node: no such class.
→
2 · Plugin_A\registered first by load order. Plugin_A\Summarizer_Node is a concrete Node subclass: cached, returned.
→
3 · Plugin_B\also ships a Summarizer_Node. Never consulted again for this name, in this process.
→
no matchnull, and make_node answers unknown class: Summarizer. An abstract match is a miss, not a fatal.

A short-name collision is silent and sticky

Two active plugins each shipping a Summarizer_Node hand BOTH topologies whichever registered first; make_node raises nothing, and a later register_namespace() cannot displace the cached answer. The defence is a distinctive short name rather than load order, which is why every class in examples/example-ai-newsletter/includes/ carries a _Demo suffix. Revisit if two prefixes resolve the same type: a tiebreak rule, or an explicit registry after all.

Naming is load-bearing

Every PHP class is Word_Word; acronyms (HTTP, SSE, CLI, LRU, CI, JSON, TTY) stay all-caps. Node subclasses end _Node; helpers do not (Event_Framework, Worker_Base, CLI). Test infrastructure stays PascalCase; the one exception is the Capture_Sink_Node double, a real make_node'd Node.

The palette (Classes_CI dump) scans the composer classmap for concrete *_Node subclasses and refuses a Hidden category, an empty one, and a node_schema() carrying 'hidden' => true. After adding or renaming a class, run composer dump-autoload -o, or neither make_node nor the palette sees it.
