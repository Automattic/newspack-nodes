A TICK ends in DONE whatever fetch() did

The abstract Source_Node owns the whole request: the trigger, the dedup, the emit and the terminal marker. A connector supplies two methods, config() and fetch(), and never touches a message.

1

A TM_REQUEST reaches fill()

Core::num_int( $message[ TYPE ] ) & TM_REQUEST is the whole test. The dashboard's Collect button and request_node github TICK mint the same message. No { emitted } reply goes back to the caller.

2

try: fetch( $this->config() ), then one pass over the items

config() reads the node's verbs and opens the Vault pointer; fetch() blocks on the network and returns normalized items. Both are the connector's.

fetch() is synchronous, so DONE is minted after every item this TICK produced and rides the same path behind them. One failing source cannot stall collection: it reports DONE with nothing ahead of it.

The item contract, from normalize_item()

{ source, id: "$source:$id", title, url, body, timestamp }

The id is namespaced so a GitHub #release-5 and a Linear ENG-5 never collide in the dedup set; the bare id each connector passes must already be stable per item. Title, url and body go through Core::str(); a date that will not strtotime becomes timestamp 0 rather than a throw. Downstream, the summarizer cannot tell a merged PR from a blog post, and does not need to.

$seen is process memory and dies with the worker

A fresh worker re-emits whatever its next fetch still returns. Deliberate: Digest_Builder_Node dedups on the same id, so the digest stays correct and only the summarize and score stages upstream pay for the repeat. A TICK-driven source has no Consumer offsetlog to co-commit a snapshot into, so the add_snapshot_node route the digest uses is unavailable here.

What the base declares for every connector

The constructor calls auto_wire_interpreter(), which reads node_schema()['commands'] and mounts a sibling Command_Interpreter_Node named {node}:config; that is what makes cmd github:config set_vault_id … lines work. source_schema() hands each subclass one shape: category Source, one TICK request, and accepts_fill false, because a source mints messages and consumes none.

Source_Node is abstract and declares no node_schema(). make_node Source returns null rather than fataling: resolve_class() skips an abstract match and keeps scanning the remaining namespaces.
