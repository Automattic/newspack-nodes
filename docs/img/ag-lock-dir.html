A lock is a directory: mkdir claims it, a heartbeat file keeps it, and a stale one is stolen

Lock_Node is mkdir-based advisory locking with a PID-stamped heartbeat, atomic on NFS, tmpfs and ext4 with no flock, no daemon and no DB row. Workers hold one per slot; Partition::allow_large_writes() holds one per partition.

heartbeatthe holder's PID; its mtime is the liveness clock, touched every HEARTBEAT_INTERVAL_S 10 from should_continue()
startedacquire() timestamp; wp nodes status reads uptime off it
restarta sentinel: PRESENCE says exit, then refill the slot. There is no clear_restart(): the next acquire() unlinks it in write_acquire_files(), release() takes it, and a steal discards it with the dir
stopa sentinel checked FIRST: exit and leave the slot empty; the persisted deploy hold is what keeps it empty afterwards
reloada watermark compared by CONTENT — time().'.'.bin2hex( random_bytes( 6 ) ), rewritten on every call, never unlinked by its consumer: mtime resolves to a second and one save writes several options

force_release_at() unlinks all five before the rmdir, because rmdir() takes only an empty directory and one survivor turns a clean release into an orphan peers steal.

restart_reason(): three answers on every drain tick

restart requested — the restart sentinel is present. lock heartbeat gone — the file vanished. lock stolen by pid N — PID-content theft. Every stat clears the cache first, or a long-running worker never sees a flag another process wrote. The worker exits cleanly on any non-empty answer; stop_requested() is checked before it.

Signalling into a stranger's dir

request_restart_at(), request_stop_at() and request_reload_at() need no instance. All three funnel through write_flag_at(), which refuses before touching disk when the dir does not exist — the lock dir IS the channel, with no queue behind it, so a slot reading down or idle takes nothing and Requested restart for N worker(s) can name fewer than the fleet — and when Config::write_denied(): as root the file would land unwritable by the workers.

Why the reload watermark is different

restart and stop signal by presence; reload signals by content. Fleet_Node::take_reload_watermark() acts whenever the content differs from what it last acted on and never unlinks: consuming by unlink would lose a request landing mid-reload, and comparing survives a steal. Losing the file on release costs nothing — the successor boots on fresh config.
