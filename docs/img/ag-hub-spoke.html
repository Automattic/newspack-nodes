A hub pulls a spoke's partition over SSE and pushes commands over HTTP, and one link owns both wires

Remote_Link_Node patrons three hidden siblings; Remote_Source_Node extends it and adds Durable_Reader's cursor to the pull. The url and credentials come from the Vault entry the link's <vault-id> names, never from a caller, and every command it signs verifies at that one spoke.

The pump valve: the one queue in the runtime

SSE_In appends inside the drain loop and the 100 ms tick drains, so the buffer grows between ticks. Past PUMP_DISARM_BYTES 512 KB, pump_maybe_disarm() (from on_message) pulls the easy handle out of the multi: libcurl stops reading, the kernel buffer fills, and the TCP window closes on the spoke. pump_maybe_arm() (from get_batch()) re-attaches under PUMP_ARM_BYTES 256 KB. One threshold would stop-start the spoke on every line.

The channel ticks ten times a second

TICK_INTERVAL_MS 100 is below the Router's cadence, so the link holds its own Event_Framework slot and list_timers shows event_framework — expected, not a spinner. fire() latches its housekeeping on the integer wall-second: the patrons, staleness, the queued reconnect, the heartbeat mint every HEARTBEAT_INTERVAL 15 s, the status publish. The other nine ticks are Remote_Source's pump.

Connects queue on _connect_timer (Connect_Queue_Timer_Node), one per INTERVAL_MS 500, so a hub reconnecting to many spokes opens them in single file instead of colliding on a spoke's SSE slot pool; the timer removes itself when the queue runs dry.

What the pull records, and what it cannot report

Durably: <name>:<remote_partition>:offsetlog and :deadletter, the same contract Consumer has. The offsetlog dir must carry <topology>, because a cursor belongs to a FLEET and two hubs pulling one spoke must not share it. Records leave through Durable_Reader::forward_line(), stamped like a Consumer's; only the plain channel stamps FROM=<link>:sse-in/<remote trail>.

A pull is not a read: STEP is inert, PAUSE disconnects, a seek forwards a sentinel to the spoke. And Remote_Source_Node has no probe_stats(), so it mints no Probe_Record: no row in wp nodes status, the Workers dashboard or the consumer-lag alert. An empty consumer table on a hub is not a caught-up aggregation.

fill() relays outward, and the schema does not say so

A link consumes TM_COMMAND|TM_RESPONSE and TM_COMMAND|TM_ERROR as its heartbeat reply and hands everything else to send(), off to the spoke's /command. Remote_Link_Node declares accepts_fill => false and Remote_Source_Node inherits it, overriding neither fill() nor send(), so a connect_node into either ships local traffic off-site with no port drawn and no warning.

A rotated credential reconnects without a recycle

A Vault write fires newspack_nodes/vault/changed: the session is forgotten, and a reload watermark lands in the lock dirs of every topology whose graph declares a Remote_Link or Remote_Source. The next _fleet scan fires RELOAD, subscribe_reload() drops the patrons, and the link reconnects under the new password without a process recycle.
