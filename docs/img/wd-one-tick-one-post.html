One router tick is one POST, however many slices ride it

The Router owns the batch bracket: it locks _http, notifies every hitchhiking timer, and flushes in a finally. Three Fetchers fan out inside that bracket and their three commands leave in one request; a fourth slice adds a command, not a POST.

_router

Fires every ROUTER_TICK_MS, 1,000 ms, on its own slot.

Timer → Tee

insights:timer rides the Router's TIMER channel; insights:tee fans its tick.

Three Fetchers

Each holds one configured verb and an outbox of asks in flight.

_shell → _http

The observe-only Tap, then the HttpOut egress that buffers while locked.

Server

/newspack-nodes/v1/command routes each command to insights-demo.

1RouterNode.fireCb() opens the bracket: _http.lock(), so every fill() reaching _http buffers instead of posting.
2notifyTimer() calls each TIMER registrant's fireCb() directly. A cadence of exactly 1,000 ms fires every tick; above it the Timer throttles to its interval on the shared wall-clock grid (ADR-17), so two surfaces on one cadence meet on the same tick.
3The Tee fans the tick to the three Fetchers. A Fetcher reads nothing off its trigger: type, VALUE and addressing are ignored.
4Each Fetcher decides what to send
No signing session yet: send nothing; the next poll carries it.
An ask is standing: re-send it only once retry_after_s (15 s; 0 disables) has passed unanswered, retire it outright at 120 s, and mint nothing new.
Outbox empty: mint ONE ask — TM_COMMAND, FROM = receiver, VALUE = { name, arguments } — mark it LOCAL (this process's own mint, and its signature), and forward with TO = _shell/_http/insights-demo.
5The Router peels _shell, the Tap passes the command through, the Router peels _http, and HttpOut pushes it onto its buffer with insights-demo as the remaining TO.
6The bracket closes in a finally, even when a subscriber throws. flush() packs the buffer once and POSTs it as one batch; a tick that buffered nothing costs no request.
7Each verb replies TO = FROM. The response hands every reply to _command_interpreter, the Router delivers it to that Fetcher's receiver Tee, the Tee fans it to the view, and last to the Fetcher, which takes the ask off its outbox.

What stops the tick from fanning out

Hidden tab: timer.stopTimer() unregisters the Timer from the Router's TIMER channel, so the tick fans out to nothing and nothing POSTs; visible again re-arms it and delivers any first load still owed.
paused: the same stop while a surface is open — a drag in flight — except that a first load still owed is delivered.
enabled: false: no first load, no timer, no named node; flipping it true delivers the first load then.
pollNow(): marks the poll due and runs the Router's tick, so a filter change refreshes inside the bracket without waiting out the cadence.

Below 1,000 ms the batch is gone

useBatchedPoll throws a TypeError naming the timer for any intervalMs under 1,000, because that floor is TimerNode's own hitchhike threshold. A sub-second timer takes a setInterval slot of its own, outside the lock/flush bracket: one POST per slice per tick and nothing batched. Sub-second work rides useRouterTick, a passenger on the Router's own tick.

A mount opening a bracket of its own would make the tick pay for a second POST, which is why useBatchedPoll opens none.
