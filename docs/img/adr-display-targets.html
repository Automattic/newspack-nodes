A node may declare a destination it writes to without routing through it

ADR-7 names two destination kinds. A third exists in practice: a Partition a node fills directly at flush, or a TO stamped per message from a conditional route. Neither appears in target(), so without a declaration the console draws those destinations with no inbound edge while they fill.

sink — physical
What fill() forwards to. A node reference. Drawn from the graph; never part of this decision.
target — the routing contract
Node::target(), verbatim. Scalar unless the node fans out. fill() reads it alone; dump_config() round-trips it as connect_node lines; a console mutation reads and patches it. This is the target key of dump_metadata.
extra_targets() — a declaration
The destinations a node writes WITHOUT going through target. Flame_Builder_Node resolves its stats-mirror Partition by name through Core::node() and fills it at flush; Request_Builder_Node stamps TO per message from one of four routes. Returns list<string>; nothing routes through it, and it must never acquire a caller in fill(). Prose the class keeps honest: nothing detects drift between it and the actual writes.

display_targets(): the union, consumed by presentation only

target_list( target() ) first, then the extras, de-duplicated, empties dropped. It feeds ls's TARGET column and dump_metadata's targets key, always a list, which is what edges are drawn from. Two keys because a flattened list cannot express fan-out, and the connect/disconnect verbs need the distinction.

Routing target set, one extra:0firehose:partition1stats-mirror:partition
Tee with two, one extra:0request-builder1error-log2stats-mirror:partition
Empty target, one extra:0stats-mirror:partition← index 0 is presentation-only here

The union is POSITIONAL, so index 0 is the routing target only when one is SET. A consumer slicing [0] as "the target" presents a display-only destination as the routing contract. One needing the routing value reads target; one that must split the union splits by the routing COUNT, never at a fixed index.

Rejected

Widening target to hold the extras: a display-only entry would replay as a route that does not exist. Inferring edges from node class in the console: one plugin's write topology inside the substrate's renderer, the boundary ADR-18 draws for locate_by(). Letting each dashboard synthesize the missing edges: three consumers, three shapes, and only the node knows where it writes.

This does not license a second physical output

ADR-7's reopen condition stands: a true second physical output means reintroducing edge deliberately, and Flame_Builder_Node's direct partition write is the case that would trigger it. Declaring makes an existing write VISIBLE; it does not make it a supported way to build new ones. Revisit if anything routes on display_targets(), or if edge arrives and absorbs the physical-write case.
