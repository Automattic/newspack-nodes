Four essentials rig a standalone plugin, and cache-cozy ships a file for each

A real plugin installs on a site that already has the substrate. Declare the dependency, defer the wiring, borrow the test bootstrap, copy two lint configs, and let a tag build the zip. The sibling newspack-cache-cozy is the minimal fully-rigged reference: one node, a mu-plugin drop-in, and every file below to copy.

a. Depend · the bootstrap
/** * Requires Plugins: newspack-nodes */

WordPress 6.5+ keeps the substrate active. It guarantees presence, never a version.

add_action( 'plugins_loaded', function () { if ( ! class_exists( '\Newspack_Nodes\Timer_Node' ) ) return; if ( ! method_exists( Bootstrap::class, 'version_at_least' ) || ! Bootstrap::version_at_least( '0.54.0', 'My Plugin' ) ) return; $load(); }, 11 );

Plugins load alphabetically, so a slug sorting before newspack-nodes is included before the substrate's classes exist. Every plugin file is included before plugins_loaded fires, so any priority is late enough: cache-cozy uses 11, the bundled example 12.

Below the floor the plugin goes dormant behind an admin notice, on substrates from 0.54.0 on; older ones have no notice, so the method_exists guard is what covers them, in silence. scripts/check-substrate-floor.sh computes the floor: it collects each substrate API you call through PHPStan, resolves each to its declaring class, and names the oldest tag defining all of them.

b. Test · tests/bootstrap.php

Declared first wins, so the layers stack in this order.

1. your stubsif ( ! function_exists() ) stubs for only the WordPress functions your plugin needs to behave differently: an option store with a test seam, a capture-shaped add_action.
2. the substratetests/Helpers/wp-shims.php, the canonical WP stubs filling in what you skipped; the substrate plugin from its sibling checkout; tests/Helpers/TestCase.php; tests/Helpers/CaptureSink.php.
3. your codevendor/autoload.php, your classmap, and any mu-plugin drop-in.

Each test builds a message, calls fill() and asserts on a Capture_Sink_Node. Extend \Newspack_Nodes\Tests\TestCase: its setUp resets Core and pins Cache_Backend::$apcu_usable to a closure returning false. local_first() prefers APCu, so on a host with CLI APCu enabled a test seeding Core::$memd sees its claims land where the fixture never reads, and passes or fails by the host's php.ini. A hand-rolled harness sets the pin and restores it, because public static state outlives the test that wrote it. $apcu_cache_info and $apcu_sma_info are the sibling seams behind the expunge and free-memory figures.

composer require --dev phpunit/phpunit:^10.0 cd tests && ../vendor/bin/phpunit

A tests/phpunit.xml names bootstrap="bootstrap.php". Run the vendored binary, never the one on PATH: an 11.x loader over a 10.x vendor tree dies with DispatchingEmitter::exportsObjects, which is why every plugin in the family pins 10.x.

c. Lint · two configs and scripts/
phpcs.xml.distthe WordPress-VIP-Go ruleset
phpstan.neon.distlevel 10 + phpstan-strict-rules, minus the five rules that fight WordPress idioms: empty(), truthy conditionals in if and in loops, the short ternary, variable variables
scanFiles: - ../newspack-nodes/newspack-nodes.php scanDirectories: - ../newspack-nodes/includes

scanDirectories resolves your extends Timer_Node with real types; scanFiles adds the root file, where NEWSPACK_NODES_VERSION is defined. Point both at wherever your substrate checkout lives.

Your own bootstrapFiles stays your plugin's root file, so PHPStan sees the constants it defines. Dev deps: automattic/vipwpcs, phpstan/phpstan, phpstan-strict-rules, szepeviktor/phpstan-wordpress, beside the pinned phpunit; cache-cozy's composer.json is a ~50-line copy-and-rename.

scripts/copied wholesale. "post-install-cmd": [ "git config core.hooksPath scripts" ] puts the tracked pre-commit and commit-msg under Git; each pre-commit runs sync-shared-scripts.sh first, refreshing the rest from a sibling substrate checkout and staging what changed.
reorder-node-methods.phpholds a Node subclass's methods in newspaper order
lint-comments.phpholds an inline comment to one line. Both run through lint-staged. wp nodes scaffold plugin writes none of this.
d. Release · a tag ships it
build-release.shstages via .distignore, runs composer install --no-dev --optimize-autoloader, zips the plugin dir
.github/workflows/release.ymltag-triggered: runs the script and publishes the zip with the matching CHANGELOG.md section as the notes
git tag v1.2.3 && git push origin v1.2.3

cache-cozy's pair works as-is after a slug rename.

uninstall.phponce your plugin stores options: runs only on delete, and deletes every option row under your prefix, transient rows and every site on multisite included

In lockstep with the substrate, the header and a presence check suffice

When the plugin ships with the substrate, Requires Plugins plus class_exists is the whole story. "Present but too old" is a real case only on sites you do not control; then the canonical handshake, one mechanism and one admin notice, replaces per-symbol capability probes. Bump the floor only when you adopt a newer API, and set it to the oldest substrate you test against.

Dashboards are a separate story

Everything here is server-side PHP. A React admin dashboard means the substrate's shared-JS build, the @newspack-nodes/shared alias, esbuild and jest; that is writing-a-dashboard.md. This guide stops at a fully working, fully tested, headless node plugin.
