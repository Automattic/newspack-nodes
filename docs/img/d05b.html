Three roles, and a ceiling that only subtracts

Authority splits by blast radius. Each role resolves to a WordPress capability through one filterable map, and a verb declares the role it needs in its schema. A verb that declares nothing gets manage.

read

Stock: manage_options

Installed: newspack_nodes_read

The floor at the command door: every batch needs it.

The dashboards, both event streams, and the read-only builtins every dashboard drives, such as list_nodes.
Every service verb whose schema declares read.
The raw firehose, live on the stream and record by record through raw-logs read_message: request URLs, hooks and payloads. Know what you grant.

tune

Stock: manage_options

Installed: newspack_nodes_tune

Declared configuration and application data, each bounded by a schema.

Substrate settings, read through the declared schema.
Saved dashboard layouts.
The Event Logger's logging rules, which decide what the firehose records.

manage

Stock: manage_options

Installed: newspack_nodes_manage

The default for any verb that declares no role.

Fleet control: starting, stopping and restarting workers.
The credential vault.
Minting sessions and revoking them.
The base interpreter's graph verbs, make_node among them, which build and rewire the graph.
# Swap the three roles off manage_options and onto capabilities of their own.
wp nodes caps install
# Grant read and tune to a log aggregator's account.
wp nodes hub-user <login>

What the install does

It grants all three capabilities to every role already holding manage_options, so nobody loses access on the day it runs, and creates newspack_nodes_hub with read and tune only. A hub user's application password can read the stream and set the logger's options. It cannot restart the fleet or read the vault.

A scope states authority, never requests it

The auth endpoint clamps a requested scope to the highest role its minting user holds, and the response says which role came back. Verifying a command installs that scope as the ceiling over it, and the capability map must still say yes underneath. A manage session minted by a read-only user is a read session.
