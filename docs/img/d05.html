A command's round trip through the door

Nine hops carry one command from its minter to a verb handler, and its reply back into the same HTTP response. The door authenticates the request and signs nothing; two gates inside the interpreter decide the command.

Minter

The browser shell, the attached wp nodes cli, or a hub addressing a spoke.

The door

POST /newspack-nodes/v1/command. The controller is also the node _output.

Router

Splits TO on /, peels the head, and forwards to the node it names.

Interpreter

The process's own _command_interpreter, or a Service_CI_Node such as the topology catalog.

Handler

One entry in the interpreter's verb table: a callable and a declared role.

1TYPE carries TM_COMMAND; VALUE is { name, arguments }, a verb and a flat list of strings. The minter signs before the command leaves its process: wp nodes cli under the site's secret, a browser or a hub under a session key.
2WordPress authenticates the request, requires the read role, rate-limits per user, and stamps _output onto each command's FROM. The door signs nothing: authority comes from the minter's signature and nowhere else.
3TO and FROM change in transit, so the signature covers neither. It covers [ TIMESTAMP, name, arguments, nonce ] and nothing else.
4Gate 1: the signature names the minter
One policy stands at every Command_Interpreter_Node, in a worker, at the command endpoint and behind a dashboard's event stream: admit a command carrying Message::LOCAL, which is built in this process, and otherwise verify or refuse.
Otherwise VALUE.auth must verify. The TIMESTAMP is at most 20 s old or 10 s ahead; sig matches the HMAC recomputed under the resolved key; nonce claims once through an atomic cache add, so a replay fails under a valid signature.
The session handle rides outside the signed string. Its scope becomes the ceiling over this one command.
Refusal replies unauthorized: <verb>, and the batch answers 401.
5Gate 2: the capability map says yes
The verb's schema declares read, tune or manage. Silence means manage.
The base interpreter's graph verbs, make_node among them, declare nothing, so the door pins them at manage; an exception list of read-only builtins such as list_nodes, which every dashboard drives, answers read.
The ceiling only subtracts. The user's capability must still be there.
Refusal replies permission denied: <role> capability required. The batch still answers 200: the signature passed.
6The handler runs and returns a result, or throws.
7The reply carries TM_COMMAND | TM_RESPONSE, or TM_COMMAND | TM_ERROR when the handler throws or a gate refuses. TO is the inbound FROM; id and key are copied; VALUE is { name, arguments, payload }.
8The Router walks the reply back to _output, whose fill writes the packed reply into the HTTP body.
9The status rides with the first reply. 200: a reply is on the wire. 202: the batch routes on to a worker, and replies are due on the open event stream. 401: a signature failed.
