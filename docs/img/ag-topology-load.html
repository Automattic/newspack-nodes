A topology name resolves through three kinds of directory, runs as commands, and a broken file costs what its catcher decides

A .tsl is a script of the REPL's own verbs, evaluated once at boot against the worker's _command_interpreter; the graph it leaves in Core::$nodes_by_name is the worker. Topology_Registry answers where a name lives, Topology_Loader runs it, and Topology_Analyzer reads it without running it.

Topology_Loader::load( $name, $partition, $sink )

<partition> and <topology> go into Core::$var first; every <ns:key> token (<config:logs_dir>) resolves through the resolver its namespace registered at boot, so the loader installs no config of its own. <topology> names the FLEET, so two topologies can declare byte-identical Consumer lines — an include collapses them to one reader — while each standalone fleet keeps its own offsetlog. The Shell runs with want_reply( false ), so no boot reply routes to an _output no worker has.

Fatal: the worker returns load_failed

fatal_errors( true ) turns exactly two conditions into throws: an include cycle, and input still pending at end of file (an open quote or a backslash continuation). The worker logs, releases, and does not respawn.

Per statement: the worker still reports ok

A typo'd type, a make_node conflict, a connect_node to nothing, a verb the secure level refuses: interpret() catches it and stderr reads error from TM_NOREPLY command: …. The rest of the file runs, so a half-built graph is the normal outcome of one bad line.

include takes a registered NAME only — a slash, a backslash or .. is refused — with #pragma once per top-level script, and a secure / insecure line inside an included file is ignored. Every stock topology ends with secure.

Topology_Analyzer reads without running, and its throw is deliberate

statements(), the flatten every reader goes through, raises RuntimeException on an unknown topology, an unknown or cyclic include, or a make_node two files declare differently, and write_set(), find_conflicts(), resolved_resource_dirs(), resolved_node_dirs(), segment_size_overrides_for(), declares_node() and includes() all let it out. An empty write set reads as "no conflict" to one gate and "every log is an orphan" to another, so the safety gates let the throw through and the display surfaces catch it.

An unknown NAME is the asymmetry: graph_for(), write_set(), segment_size_overrides_for() and includes() return empty for one, where statements() throws.

Frontmatter is read statically

var lines Topology_Analyzer::frontmatter() parses without executing the file; synthesize_entry() folds three into the catalog: num_partitions, stale_timeout, on_demand_idle, each through the validated Core::num_int. Zero or negative takes the fleet default for the first two — zero partitions is no fleet, a zero timeout is respawn churn — while 0 is on_demand_idle's meaningful "stay resident".

The write set decides co-activation

Two topologies whose write sets overlap would put two processes on one file. A partition BOTH declare with the same make_node line is a shared multi-writer log and no conflict — appends at or under PIPE_BUF are atomic — unless either side lifts the write cap, which asserts a sole writer. Offsetlogs and dead-letter dirs stay sole-writer, so any overlap there conflicts.

A set_*target line is a routing edge

Both expand() and graph_for() read a command_node <node>:config whose verb matches /^set_\w*target$/ as an edge; setting the slot again MOVES it, and an empty target clears it. ELN's request-builder.tsl routes four of five outputs this way, so a reader who trusts connect_node alone sees one output where there are five.
