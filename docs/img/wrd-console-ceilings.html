A floating transcript's ceiling comes from a measured box, never from the viewport

ReplFooter accepts maxHeightPx and prefers it everywhere the ceiling is read: the drag, the keyboard nudge, double-click to maximize and the re-clamp on resize. Its viewport fallback is right only on a full-page console with exactly this chrome above it, so both hosts measure their own frame and hand the number in.

The transcript reports back the other way

ReplFooter calls onOverlayHeightChange( px ) with the pixels its open transcript covers of the canvas, 0 while collapsed → both hosts feed it into useGraphSurface's transcriptOverlayPx → the canvas reads it as ChromeProvider's bottomObstructionPx → autofit fits the graph above the transcript.
A host that measures a ceiling and skips the callback ships a transcript covering nodes autofit still believes are clear. That is why useChrome() throws outside a ChromeProvider instead of defaulting the obstruction to zero.

What is shared across the two hosts

The dragged height persists under one key, newspack-nodes:topology-console:repl-height: a resize on the console changes the height the overlay's Console tab opens at, and the reverse. One operator, one REPL habit.
The camera persists as a delta from autofit, { dcx, dcy, zoom }, never an absolute viewBox: { 0, 0, 1 } is autofit at any size, and a box without positive width and height or an unreadable zoom returns null rather than an infinite or mirrored view.
Everything but the ceiling: ConsoleShell owns the Header, canvas, footer order; useGraphSurface composes the collapse flags, overlay height and REPL state; useCompletion serves both prompts. Command history is free through consolePersistence; each host names its own transcript key.
