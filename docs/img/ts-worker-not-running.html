A worker that should be running: read the evidence, not the guess

Every state wp nodes status prints comes from a file the fleet wrote, and every reason wp nodes run prints comes from the worker itself. Six faults hide behind those rows; the bottom row names the line that gives each one away.

1. wp nodes status
one row per {topology, partition}, read from {base}/locks/
{type}.p{N}.lock.d/
live — heartbeat younger than the topology's stale_timeout, 60 s by default
stale — the heartbeat has aged past it
down — a resident topology holds no lock at all
idle — an on-demand topology (on_demand_idle > 0) scaled to zero
held — a deploy hold stands
inactive — in the catalog, not in the topologies key
live (inactive) / stale (inactive) — deactivated, its worker still holds the lock
Healthy. Uptime is the lock dir's started file; the ~595 s recycle resets it by design. A worker that dies moments after: step 2.
A peer's _fleet scan steals the lock and respawns; with no peer left, the minute cron does. Mid-restart, not dead.
The rescue case: the same two tiers spawn it. If nothing does, one of the six silent faults below is stopping the spawn.
Not a fault. A producer inside the substrate wakes it on flush; one outside is noticed only by the minute pass's wake_readers_with_backlog().
newspack_nodes_hold option set by wp nodes stop, never cleared. doctor reports fleet-hold with its age; wp nodes start lifts it.
wp nodes activate <topology> opts it in and spawns now. A fresh install activates nothing — the topologies key defaults to empty — and wp nodes types says so.
Winding down. run and restart no longer take its type.

Named stops: lock lost, lock dir gone, stop requested, restart requested, lock heartbeat gone, lock stolen by pid <n>, memory watermark (<used>MB / <limit>MB, <pct>%), db check failed 3 times. Silent by design: the max_runtime recycle and the on-demand idle exit.
Idempotent and harmless: two spawners raced and one lost.
A real I/O fault, and the one the worker also logs. Fix the path; doctor's filesystem and ownership rows are the same check.
Exactly three causes: a top-level topology name no registry answers to, an include cycle, and input ending inside an open quote or a backslash continuation. No self-respawn on any of them, because respawning would hot-loop the same bad file.

Six faults whose cause no status row names

Nothing spawns: HTTP 409 fleet_held

The spawn endpoint refuses while the hold stands. status reads held and doctor's fleet-hold row gives the hold's age; wp nodes start releases it.

Nothing spawns on a multisite subsite: HTTP 403 newspack_nodes_not_fleet_site

Locks, IPC and logs carry no blog namespace, so the fleet runs on the main site alone: Bootstrap::reconcile_fleet() returns at once off it and wp nodes restart flags nothing. The housekeeping row asks only whether the reconcile event is scheduled, which admin_init does on any site carrying an active topology. Judge the fleet from the main site.

stderr repeats refusing to spawn — topology write-conflict

Two active topologies claim one write path; spawn_each() refuses the whole set, naming both as a ↔ b (<kind>:<path>). A byte-identical make_node line is shared writing, not a conflict, unless either side lifts the cap with void_warranty or allow_large_writes, which assume a sole writer. wp nodes deactivate one.

Retention, alerts and cold-start revival all stopped

The newspack_nodes/reconcile cron event is gone. Here doctor is NOT green: its housekeeping row fails and prints the fix, wp cron event schedule newspack_nodes/reconcile now newspack_nodes_minute. Grep the error log for reconcile cron vetoed: first, or the event vanishes again.

Boots ok, graph holds only _router, _command_interpreter, _fleet, _repl

The .tsl exists but cannot be read — a root-owned 0600 file. Topology_Registry::resolve() tests is_file() alone and passes it, Topology_Loader::load() casts the failed file_get_contents() to '', and the worker self-respawns forever. doctor stays green: ownership stats the directory, not the file. Pivot in and run ls: only underscore names means never read; a partial list is a refused statement, whose rate-limited line is in the PHP error log.

Peers stop reviving each other

Fleet_Node::fire() re-throws Worker_Should_Stop and swallows every other \Throwable as a rate-limited fleet scan failed: <message>. The worker drains normally and revives nobody; revival degrades to the minute cron. Causes: a newspack_nodes/topologies provider that throws, since the scan fires that filter on every pass, or a base directory Config::get_base_directory() refuses.
