The REPL is a graph: bare, it answers itself; attached, its Router writes into a worker's IPC log

CLI_Command::build_repl_graph() mounts the same local nodes either way. Attached mode adds a Partition named after the worker and a Consumer tailing the worker's output, and sets the Shell's cwd so every default command carries TO={worker-id}.

IPC on disk: always single-partition, one dir per reader

{base}/ipc/{reader}/input/{seg}.log — shell → worker. {base}/ipc/{reader}/output/{seg}.log — worker → shell. A reader id is {type}.p{N}: dot-and-p keeps it ONE path segment, where job-worker/3 would route as "find job-worker, pass 3". The type match is greedy, so foo.bar.p3 is partition 3 of foo.bar. Filesystem permissions gate the directory, which is why the cli refuses root; the commands inside are still signed and verified.

Drain on stdin close: a TM_EOF round trip

The cli emits TM_EOF with FROM _output/$pid; the interpreter it lands on bounces it TO = FROM; the Dumper sees the echo and flips the exit flag, so every reply written before it has been drained off the output log. A 5-second deadline keeps a dead worker from hanging the cli. TM_EOF, TM_ERROR and TM_REQUEST all ride the Partition because a Partition packs every TYPE.
