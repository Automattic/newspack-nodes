The schema declares every key and its default; every file is an override

Four layers resolve one key, weakest first. The declared key set derives from the schema, never from a file, so an operator's typo cannot declare itself, and a key added after the operator's file was copied still has a value.

A key with no sensible universal value declares null, and that is identity, not a missing default: publication, script_alias, table_prefix, credentials, host paths.
weakest: the base everything else overrides

Two declaration shapes, both first-class

Where a Field carries the default, Schema::defaults() is the base: newspack-nodes, newspack-event-logger-nodes. Otherwise a static Config::config_defaults() array is: newspack-nuclear-gyrobase, which has no Field layer, and newspack-pyrobase, whose 15 Fields render settings and declare no default: against 86 keys. Declaring a key in both places is the drift this decision exists to prevent.

Schema::defaults() OMITS a keyed Field written without default:, which makes that key null on every install; a plugin using it as its base asserts completeness itself. A drift test parses the shipped file's commented lines back and holds them to the code defaults key for key and value for value.

Read through a helper that falls back to the DECLARED default

Core::num_int( Config::value( $k ) ) answers 0 for a null or blank entry; read unguarded, that 0 would collapse the max( 1, … ) behind SSE_Slot_Pool::max_streams() to a whole-host cap of one stream. SSE_Slot_Pool::budget() is the shape.

The <config:key> token resolver reads load_config() with no declaration gate, so anything in the local file resolves, while a misspelled key expands to '' behind a rate-limited warning wherever interpolation is non-strict; a schema-arg default is the one place it throws.

Rejected: the file as declaration, failing forward

A deploy preserves the operator's file, so a key added later never appears in it, and a default living only there reads null forever: sse_idle_timeout shipped inert that way, silently, for weeks. A completeness test cannot help, because it sees the file in THIS checkout while the failure is on a host whose file is older.

Rejected: the file as declaration, failing backward

Deriving the key set from array_keys( load_config_defaults() ) makes a typo self-declaring: base_directroy becomes valid, the real base_directory falls back, and the runtime writes its whole tree somewhere else with nothing in the log. Registering the file's keys so nothing is refused is the same failure.

Rejected: throwing on an unknown file key

It converts an operator typo into an outage, and the file is not ours to validate that strictly. The inverse is as fatal: with the file as the declaration, an environment without one declares nothing, the first Config::value() throws unknown config key, and every request including wp-admin fails, as Nuclear Gyrobase's did. Loud means visible, not fatal. Putting every default in a Field was rejected too: pyrobase would carry 71 Fields no page shows.

Uninstall never resolves the schema default

It is the path every unconfigured install on a host shares, and deleting it takes a sibling's live logs, locks and offsets. runtime_base_directory() resolves only the explicit sources: the option, the LOCAL_NEWSPACK_NODES_CONF file, the shipped file. Revisit if a plugin needs a default that cannot be expressed in code, a value derived from the host at runtime: the answer is a resolver called from the declaration, not a value in a file.
