What each verb does when root runs it

Workers run as the web user and own every lock, IPC and segment file. Root is refused by two verbs and fails every write that flags a worker, so no root run reports a signal it never sent; memcache flush alone warns and carries on. The exception is ingest, which writes as root and leaves the damage for later.

Is the effective uid 0?CLI::uid() answers; each verb asks for itself, cli and run at entry, the rest before each write

Refuse outright

clirun
Error: wp nodes cli must run as the same user as the workers, not root.

Both would seed {base}/ipc/ and locks/ root-owned, and the workers could never append to their own IPC again. Recovery after a run that got through: chown -R <webuser> of the base dir, which doctor's ownership row names.

Fail on the refused write

stoprestarta settings save
refused to write {base}/locks/job-worker.p0.lock.d/stop as root

Every lock dir is offered its flag, then every refusal escapes together, naming each dir and flag, and the command exits non-zero. stop has already set the hold, so the fleet stays held with its workers still running; a settings save has already written its option row, and the error says no worker heard of it.

Warn, then carry on

memcache flush
Warning: Workers were not restarted: refused to write … as root — the new scope takes effect on their next spawn.
Success: Cache salt rotated; …

The salt rotates first, and that is the flush. The fleet restart after it is refused like any other flag write, and the command says so and exits 0, because a worker picks the new scope up at its next spawn anyway.

Work as usual

statustypesdoctor

Read-only verbs need no write, so denial costs them nothing.

ingest neither refuses nor skips

It writes through Topic_Node, which materializes partition directories and {seg}.log segments under logs_dir on first use. A root replay leaves root-owned dirs and segments the workers can no longer append to, rotate or prune. Nothing says so at the time; the damage surfaces later as doctor's ownership row.

Reading a quiet result

A 0 worker(s) restart counts lock dirs that took a flag, and a missing dir holds no worker. On a fleet that is plainly live it is a multisite subsite: the fleet is network-global and runs on the main site alone, so a subsite's restart flags nobody and exits 0.
