A node that owns siblings publishes them into slots, and four cascades read the slot map

Publishing is declaring. A sibling built in a constructor is enrolled the moment publish_sibling() runs, takes the name {patron}:{suffix} when the patron takes one, and follows the patron through every rename, sink change and teardown. Nothing else reads the map.

1 · collision pre-checkcheck_name_availability() tests every slot a rename will touch: each sibling first, the auto-wired :config LAST, then the node's own name. A collision throws before anything is unregistered. Sound only because Core::$nodes_by_name is a per-process array.
2 · renameset_sibling_names() is the ONE namer, reached from the publish and from every name(), so key and name cannot drift. An override MUST call parent::; forgetting it stops naming every sibling with no symptom and no gate.
3 · sinka patron's sink() sets the same sink on every sibling in the map, so a Topic's partitions and a Consumer's sidecars forward where the patron forwards.
4 · teardownremove_node() tears siblings down with the patron; retract_sibling( $kind ) is the single-slot inverse, tearing down AND emptying the slot.

An occupied slot is refused

publish_sibling() throws sibling slot occupied: {$kind}; retract_sibling() to replace it, because a displaced sibling would stay registered and keep its handle where no cascade could reach it. Re-publishing on a second arguments() replay therefore throws; a builder that means to replace retracts first.

patron() before name()

Setting the patron after the name is refused. The patron is both the interpreter's drop and the canvas-visibility flag: dump_metadata skips patron-linked nodes, so the p{N} children never appear on the canvas and a Topic's row aggregates their bytes instead.

Publishing is atomic on failure

When set_sibling_names() refuses the composed name, the slot is emptied again before the exception propagates, so a caller's own guard rebuilds rather than serving a half-published sibling. Spell out all six geometry positions for a sidecar: an omitted one resolves to the operator's <config:*> default, not a sidecar-sized one.

Every subclass forwarding through parent::fill inherits the stamp: Hook, Grep, Echo, Log, Table, Age_Sieve, Value_Timeout, the JSON pair, Dumper's emit(), Tail's forward_line(). Shell, Callback and Durable_Reader::forward_line() address their own emits; Null, Stdout and Stderr emit nothing and never need a sink.

stamp_message( &$message, $name ): prepend to the trail

FROM = '' === FROM ? $name : $name . '/' . FROM

It returns false, and the caller must drop, in two cases: the new FROM would exceed MAX_FROM_SIZE 1024, which is what stops a cycle from growing the trail, and $name is empty (mid-construction, post-rename), which would compose a /from path the Router cannot resolve.
