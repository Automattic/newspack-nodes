How a byte from the internet reaches the operator's terminal

A terminal obeys some byte sequences instead of displaying them. Every sequence starts with the escape byte, 0x1B.

1 · Anyone on the internet

Requests a URL, or sends a User-Agent header, that contains the escape byte.

2 · PHP

Logs a notice about the request. The byte lands in wp-content/debug.log, a log source the console knows without any configuration.

3 · The operator

Opens the console, wp nodes cli, and types taillog debug to read the end of that file.

4 · The gate

Core::terminal_safe()

Every terminal writer passes its text through here. Each control character is rendered as a visible token, <1B>, rather than removed, so the operator sees the attempt.

[\x00-\x08\x0B-\x1F\x7F-\x9F] and the C1 range as UTF-8

Rendering, not refusing

A log tail contains whatever the log contains, so refusing it would deny the operator what they asked for. A remote health message has a fixed shape, so Health_Probe_Client refuses one carrying any control character. Both live in the codebase on purpose.

The one bypass

Stdout_Node::write_raw() writes without the gate, for a caller composing a sequence on purpose. Its only user is the console's clear command.

Questions 4a and 4b

Is rendering the right choice for a log tail? And is a UTF-8 terminal the right scope, given that escaping every high byte would mangle all non-ASCII text in every log?
