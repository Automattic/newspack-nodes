A message is seven fields. A node is one fill().

Every node takes the same argument and answers to the same method, so any node composes with any other. The envelope carries the addressing; the node reads the payload and does one thing with it.

1A node fills its sink

fill() takes the message, does one thing with it, and returns nothing. Then the node hands the message to its sink, the physical next hop.

2A target stamps an empty TO

A node may carry a target, a path. Any message it forwards with no destination yet gets that path stamped into TO. Steering the graph is setting targets, never rewiring sinks.

Fan-out is a Tee

Every live target gets its own copy, addressed so the router carries that copy down whatever path remains. Delivery follows connect order.

A transform is a Hook

A Hook fires one WordPress hook per message. An action observes the payload; a filter replaces it. Another plugin reaches the stream through add_action and add_filter, shipping no node at all.

A new behavior is a new fill() body

Write it, filter it, copy it, or hand it to a WordPress hook. That is the whole extension surface.

Nodes never call each other's methods

They pass messages. That is what makes a test three lines long: build a message, fill the node, assert on what came out.
