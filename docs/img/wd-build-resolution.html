One base path resolves the substrate for the build, the tests and the page

NEWSPACK_NODES_SRC names the substrate's src; alias-map.cjs derives every alias from it for esbuild and jest alike; buildDashboards writes the four files Admin::enqueue_react_page() resolves by the literal name index.

What each import becomes

Ten externals in WP_EXTERNALS: @wordpress/element, api-fetch, components, blocks, block-library, i18n, data, react, react-dom, react/jsx-runtime. Each import is rewritten to its window.wp.* or window.React* global, and its handle lands in index.asset.php.
Bundled: everything else — @wordpress/icons, d3, @noble/hashes — because WordPress registers no runtime script for it. .svg and .png inline as data URLs.
Aliased: the three @newspack-nodes/* specifiers inline the substrate source into this bundle; a bare import inside that source resolves from the substrate's tree first, then nodePaths.
keepNames: true, because Node.shellClassName() and the REPL's list_timers rows read constructor.name.

The entry must be index.js

Every output is named after the entry file, and the registrar looks for the literal name index inside dir. One outDir holds exactly one bundle.

Admin::enqueue_react_page( [ handle, page, dir, url, version_fallback, style_deps, localize ] ), on admin_enqueue_scripts
1
Page gate. page is one ?page= slug or a list; anywhere else the call returns null.
2
file_exists( dir/index.js ), else null: nothing enqueued, no PHP error, no 404, nothing in the console. An unbuilt checkout, a zip that never ran npm run build and an entry renamed to dashboard.js all present this way; the mount div still prints empty.
3
Manifest. Dependencies and version from index.asset.php. With no manifest, the dependencies fall back to wp-element, wp-components, wp-api-fetch, wp-i18n and the version to the bundle's filemtime(). version_fallback stands in for a manifest with no string version, or an unreadable filemtime(); omit the key and it falls to NEWSPACK_NODES_VERSION, the substrate's version rather than yours.
4
wp_enqueue_script in the footer, below the mount div, which is why index.js can still wait on DOMContentLoaded.
5
index.css under style_deps (default [ 'wp-components', 'newspack-nodes-ui' ]), versioned by css_cache_version(), its own content hash, so a SCSS-only rebuild busts the cache; index-rtl.css rides as RTL data.
6
wp_localize_script emits NewspackNodesData = { restUrl, nonce, …localize }. The JS defaultTransport() reads exactly that to authenticate POST /command: the registrar and HttpOut's transport are the two ends of one wire.

Three stylesheets, one cascade

newspack-nodes-theme — the --np-* tokens: palette, type scale, spacing scale. Defined on .newspack-nodes-theme.
newspack-nodes-ui → depends on theme — component appearance under .newspack-nodes-ui.
newspack-nodes-graph → depends on ui — the topology-canvas artwork; name it when the page mounts DebugOverlay or GraphView.

One handle, one enqueue site. wp_localize_script() concatenates: two enqueues of one handle emit two var NewspackNodesData statements and the later assignment wins whole.
