A timer takes one of two clocks, and a long job has to ask for the stop it cannot hear

Timer_Node::set_timer() picks the mode: a named node at or above the Router's cadence rides the Router's one-second tick; everything else holds its own Event_Framework slot. Inside a job that starves the loop, pump() runs the worker's continue-predicate by hand.

no → own slot (MODE event_framework)an unnamed node, the Router itself, or an interval shorter than the cadence. Needs a concrete interval or throws. Event_Framework::set_timer() seeds next_fire = Core::$now + interval. A Consumer at 0 / 100 ms and a Remote_Link at 100 ms sit here.

The two modes disagree about the FIRST fire

A boot-time burst comes from the first row: a 300-second collector and a 15-second probe both fire on the tick after arming. A oneshot in either mode fires once; fire_cb() calls stop_timer() BEFORE the sink check, which zeroes interval_ms, so a sinkless oneshot is disarmed without ever dispatching and a node re-arming a oneshot at the bottom of its own fire() leaves the loop on its first early return. A self-pacing node keeps a RECURRING timer and calls set_timer( $next_ms ) only when the cadence changes.

pump() and stop_check() — the cooperative-stop seam inside a blocking job
who calls itPartition, on every record it writes, so a long fill() that starves the drain loop still hears its stop.
throttleonce per PUMP_INTERVAL_S 1.0 against the live clock; going through right_now() also un-freezes Core::$now at pump cadence.
what it runsthe parked continue-predicate should_continue( mid_work: true ); on false it raises Worker_Should_Stop, which unwinds the whole fill() stack.
only under Worker_Baseit no-ops unless drain( …, cooperative_stop: true ) is active, so a cli or SSE drain can never be thrown out of.
stop_check()the same decision, unthrottled — for a caller that needs the answer NOW, such as a subprocess render that may have outlived the lease.
never from stderrboth return early while Core::in_stderr(): a stderr write is not a stop boundary, and logging the stop would self-throw.

Deferred_Clean_Stop — the write side of that protocol

A snapshot node forwarding into a Partition mid-fill() still owes the message its own bookkeeping. guarded( $forward ) catches the Worker_Should_Stop and holds it (first one wins; a non-stop throwable propagates to the Consumer's dead-letter path); raise_pending_stop() re-raises it at exit as a FRESH Worker_Should_Stop_Clean, which Durable_Reader::drain_buffer() reads as permission to commit PAST the record. Call clear_pending_stop() at entry and raise_pending_stop() at every exit.

cURL handles ride the same wait

Each node registers its own EASY handle with register_curl_easy( $node, $easy ); all attach to one lazily-created multi. While any is registered the tick sleeps in curl_multi_select instead of usleep, and a completion is routed by the handle's spl_object_id to its owner's on_curl_message(); a node without that method is skipped. Event_Framework::$curl_poll is the test seam standing in for curl_multi_exec + curl_multi_info_read. There is no FD registration path: file polling is timers.
