The operator's loop, and the ladder a release climbs

A deploy is four commands in one order, and the order is what keeps a live worker from reading half-replaced files. A release adds one rule on top: tag the substrate before any plugin that pins it.

One deploy, across three lanes

Install without the hold, and the fleet reads half-replaced files.

A live worker's autoloader breaks mid-record, and the Consumer quarantines the record in flight as poison. wp nodes stop exits non-zero when its wait expires, which is how a scripted deploy learns the drain failed instead of installing over live workers. When the files are already in place, wp nodes restart all is enough and still necessary: a worker holds the old class for the rest of its 595-second lifetime. Skip the build and the deploy installs a stale zip, which PHPUnit, running from the source tree, cannot notice.

What a slot reads, and what moves it

wp nodes status: one row per partition

wp nodes doctor: eight health rows
cache backend · filesystem · ownership · housekeeping · config keys · worker liveness · consumer lag · dead letters, plus fleet-hold while a hold stands. Warnings warn; a critical row exits non-zero.

wp nodes run <type>

Runs one worker in the foreground and prints its exit reason, for a worker that spawns and exits at once.

wp nodes memcache flush restarts the fleet

It rotates the install's cache salt, orphaning every Newspack plugin key at once and no co-tenant's. The restart follows because a live worker keeps writing under the old prefix until it respawns.

Inside a live worker: wp nodes cli <type>.p0

The REPL pivots into the running process

ls -c
Lists the worker's nodes with their counters.
dump_node
Prints one node's state.
stats
Reads throughput.
list_timers
Finds a spinner: a row whose next fire is at or below zero while its fire count climbs.
profile on
list_profiles
Ranks nodes by their own time.
dmesg
Shows the last hundred stderr lines.
taillog
Tails a registered log source.

What the REPL finds goes back to the top: fix the code, build the zip again.

Attach as the web user. Root is refused.

A root session would seed the worker's IPC directory with files the worker itself cannot write, and the worker stays locked out after the session ends.

Releasing: the substrate before its consumers

Three rungs, in this order
1

Tag the substrate and push the tag. scripts/bump-version.sh rewrites the version in every file that carries it. Promote the [Unreleased] section of CHANGELOG.md, commit, and push a strict v<major>.<minor>.<patch> tag; a -beta suffix is a silent no-op. The workflow builds the zip, takes that changelog section as the notes, and publishes.

2

Bump each consumer. Its bump script rewrites the ref: pin in release.yml to the substrate version in the working tree, and refuses when that version carries no local tag. A consumer tagged by hand never runs the script, which is why rung 3 exists.

3

Verify the published asset. Identical bytes mean the pin is right.

gh release download v<version> -R <owner>/<repo> -p '*.zip'
unzip -q <plugin>.zip
diff -rq <plugin>/build <local-checkout>/build

A green workflow proves nothing about which substrate the zip carries

The event logger and intelligence bundle substrate code through the @newspack-nodes/* alias. A local build resolves it to the sibling working tree; CI resolves it to the ref: pin. When the two disagree the build still succeeds, because the shared code is only older.

The pin is not the floor

ref: decides which substrate source CI bundles.

version_at_least() in the plugin's loader decides which installed substrate the plugin runs against, going dormant behind an admin notice below it.
