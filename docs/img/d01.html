A worker is a PHP request that outlives its caller

Managed hosting gives a plugin four things and no process that stays up: PHP requests that end, WP-Cron, a shared memcache tier and the REST API. The runtime makes a resident worker out of those parts. Lanes are the parts; numbered hops are one worker's life, from the spawn POST to the POST that starts its successor.

The host gives

Peer worker or WP-Cron

WP-Cron fires on traffic and drifts on quiet sites. Its pass once a minute spawns what is due, reaps stray locks and prunes retention: the cold-start tier.

The host gives

REST API

POST /workers/spawn

POST /command carries every dashboard verb.

Two SSE streams tail logs to the browser.

The runtime builds

Worker job-worker.p0

One request, made to end late. It runs one topology: a graph of nodes a .tsl file declares in shell verbs such as make_node and connect_node.

No supervisor

Every worker scans its peers every 15 seconds and respawns one whose heartbeat is stale. A fleet with nothing left running is revived by the WP-Cron pass, once a minute.
