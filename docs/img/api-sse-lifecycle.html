A stream's life: one slot lease, five events, two clocks and three ways it ends

GET /messages/stream holds one PHP-FPM child from the slot acquire to the finally that releases it. The server reads the lease on every tick and never refreshes it; the client's workers heartbeat is the only thing that does. /log/stream is identical on the wire.

Open, in order

acquire slotOnce per stream, BEFORE any header, so a refusal can still answer 429 too_many_connections. Unwired, it hands back an unmetered sentinel lease, and the other three seams do nothing.
headersset_time_limit( 0 ), ignore_user_abort, Content-Type: text/event-stream, X-Accel-Buffering: no, Content-Encoding: none, zlib off, output buffers torn down.
retryFirst, because every close relies on it: VALUE is sse_retry_ms (default 5000). An event rather than the protocol retry: field, since the client owns reconnect. At 0 or below the client ignores it.
build the graph_router, an interpreter under Command_Auth::verifier(), this controller as _sse, an HTTP_Filter_Node as _output keyed to this pid; then one Consumer per subscription.
connectedThe handshake: PID, SLOT, OWNER, the subscriptions, the heartbeat INTERVAL and each subscription's STARTING cursor. Chased by a padding comment of exactly 4096 bytes, because a bare flush() does not clear proxy and TLS buffers.

Then, on every drain tick, about ten times a second

1
$check_slot( $lease, $partition ) false?
disconnect: KEY=slot_lease_lost, VALUE SSE slot lease lost, one JSON diagnostic line through the node stderr chain, then close. The terminal frame always means failure: the lease was taken from under the stream.
2
connection_aborted()?
The client went away: close, nothing sent.
3
No msg for sse_idle_timeout seconds (default 15; 0 streams until the client goes away)?
Idle close, so a dashboard nobody watches stops holding a PHP-FPM child: a bare EOF with no terminal event, so the client reopens on the retry schedule. A stream that opens at EOF on a source quiet ten minutes ago is already ten minutes idle and closes on its first tick; an attached worker console never reports idle, because someone is reading it.
4
2000 ms since the last heartbeat (HEARTBEAT_MS)?
heartbeat, VALUE the tick timestamp. Deliberately not data: it never defers the idle close. Glob subscriptions self-heal here: a newly matching dir opens tail-seeked, a vanished one drops, and a glob() I/O error skips the removal pass rather than re-tail every partition.
5
Anything written since the last flush?
The 4096-byte padding comment, then flush(), before the drain sleeps. Every SSE parser discards a comment. Each delivered record went out as a msg event carrying the packed Message; only those count as data.

The finally

Every Consumer, the default route, the interpreter, the filter and the router are removed and the _sse name unregistered, then $release_slot( $lease, $partition ) runs, so neither a clean close nor a throw leaves the slot held until its TTL expires. An unexpected exception writes the same diagnostic line first, tagged unexpected_exception, and is rethrown.

The four Closure seams, wired by SSE_Slot_Pool::wire()

SeamCalled
$acquire_slot( int $partition ): array{slot,owner}|falseOnce, before any header.
$check_slot( array $lease, int $partition ): boolEvery tick. It only READS: refreshing the TTL here would let a stream nobody watches hold its slot forever.
$release_slot( array $lease, int $partition ): voidFrom the finally.
$inspect_slot( array $lease, int $partition ): arrayOnly once a check has failed, to name the backend and lease state in the diagnostic. The healthy path never pays it.

A fifth, $diagnostic_log, narrows the close-context line for tests. The partition handed to the pool is the number of the first {type}.p{N}-shaped subscription, or -1; the shipped pool ignores it and pools host-wide.

The lease, and who keeps it alive

Both stream routes draw on one host-wide pool. A browser's _heartbeat node pokes every 15 s with workers heartbeat [ slot, owner ], both canonical decimal tokens from the connected handshake; the server owns the TTL and the client cannot lengthen it. A closed tab pokes nothing, so its slot frees itself one TTL after the last poke. workers heartbeat is a read verb because manage would expire every read-only stream after one TTL.

A client consuming disconnect RETAINS both halves, the machine KEY it branches on and the display VALUE, so the transport close that follows cannot replace a real reason with a generic one. SSE_In_Node is the reference: it trims each half to 512 bytes, treats a frame with an empty KEY or VALUE as fatal (ERROR, lease retired, transfer aborted), and holds what is left as its terminal state. sse-host-budget.md carries the arithmetic behind each number.
