One tick of a dashboard, in twelve hops

The page runs the same graph a worker does, in JavaScript, with the PHP runtime's vocabulary: fill, sink and target. Commands leave in one POST per tick; a reply comes back addressed TO = FROM, in the POST body or over the record stream.

@newspack-nodes/runtime: every page mounts the same two backbone nodes and wires its own onto them.
_router forwards each message by the first segment of its TO and owns the page's one heartbeat, the tick every periodic node rides.
_command_interpreter turns each console line into an action on the node table, sinks into _router like every other node, and answers with TO set to the request's FROM.
Browser, sendingthe page's graph
1A Timer ticks on the router's heartbeat.
2A Tee fans the tick to one Fetcher per verb.
3Each Fetcher sends its fixed verb, FROM = its receiver Tee.
4_shell, a Tap, forwards it unchanged; connect _shell shows each one.
5_http buffers while the router holds it locked, then one POST carries the whole tick.
Command requestthe outbound boundary
6POST /newspack-nodes/v1/command. A service node answers the verb inside the request, and the reply rides the POST body with TO set from the browser's FROM. A command bound for a worker is routed onward, and the POST answers a bare 202.
Workerthe second channel
7The worker handles the command and writes its reply to a partition.
reply in the POST body, routed by TO = FROM
Stream requestone php-fpm child, one graph
8GET /newspack-nodes/v1/messages/stream, whose subscribe argument names the partition. A Consumer tails that partition into _sse, the stream's controller, and every message routed there leaves as a msg event. The route gates on the read capability with no nonce, so a hub pulls a spoke the same way.
Browser, receivingthe same graph
9Both channels land here. A receive-only node fills each frame into the graph, the POST body's reply is filled the same way, and _router forwards each by its TO.
10The receiver Tee named in FROM takes the reply.
11A view node parses it into a render model, publishes it, forwards nothing.
12One widget draws that one node.

The pages that mount it

The station is one wp-admin page with nine tabs, four of which load only when first opened: Console, Vault, Sessions and Aggregator. The Event Logger adds five dashboards, overview, error log, gyroscope, settings and requests, plus the current-request overlay tab.

Inspecting the live graph

Any dashboard can mount the debug overlay. It reads the page's own node table and draws every live node, edge and counter, with a REPL for connect and remove. It renders nothing until ?nodes-debug=1 turns it on.

Why no node holds the whole model

One node that fetches everything has counters that never move and edges a debugger cannot read, so the overlay has nothing to draw. One verb per Fetcher, one reply per view node, one node per widget.
