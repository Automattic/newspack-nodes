The seam replaces one call and leaves everything around it under coverage

A connector's fetch() is where the network lives, and the network is the one thing a test cannot touch. The same fetch, twice: with the transport call swapped by a closure property, and with the whole method swapped by a test subclass.

Green on paper, unmeasured in fact

Coverage marks http_get() covered while its production body, steps 1 to 5, never executed in any test. The standing rule across these plugins is the closure property, never the helper-and-subclass form.

One seam per connector

GitHub and Feed carry $http_get; Linear's single GraphQL POST carries $http_post. The signature every replacement satisfies: function ( string $url, array $args ): array|\WP_Error. The suite is hermetic: cd tests && ../vendor/bin/phpunit touches no network.

Fetches block, and that is fine

wp_remote_get with a 15-second timeout is synchronous, and so is the Linear POST. Unacceptable in a web request; but connector fetches run inside a background worker, which is why the file carries phpcs:ignore notes for the VIP remote-request rules. The worker is the isolation boundary, and the same reasoning licenses the LLM calls downstream.
