A pivoted REPL is two partitions on disk, and a reply finds its way back by address alone

Attached to a worker, a line you type becomes a signed command appended to the worker's input/ directory; the reply comes back through output/ addressed to this session's pid. Nothing correlates the two but the FROM trail.

Terminal

TTY_In reads the keyboard, or fgets a pipe; _stdout writes the reply.

The cli's own graph

An anonymous Shell, the _shell tap, _command_interpreter, _router, _output (a Dumper) and _stdout, in the wp-cli process.

{base}/ipc/{type}.p{N}/

Two Partitions: input/, which every attached session appends to, and output/, which the worker alone writes.

The live worker

Its anonymous input Consumer, its interpreter, and the _repl Partition.

0Attaching resolves the worker in two steps, and a bad id is refused before either
{type}.p{N} must parse, greedily, so a dotted topology name keeps its dots. Otherwise invalid reader id: <id> (expected {type}.p{N}).
Then {base}/locks/{type}.p{N}.lock.d/ must exist, or failing that Spawn_Coordinator::wake_sleeping_worker() must answer, since an on-demand worker sleeps holding no lock. Otherwise no worker '<id>' (run `wp nodes status` to list active workers).
Neither refusal creates a ghost IPC partition. Staleness is not blocked: a stale worker is mid-restart, and the cli works once a peer respawns it.
1A line arrives as TM_BYTESTREAM. The Shell parses it, mints a TM_COMMAND stamped FROM=_output/<pid> and TO={type}.p{N} (the cwd), signs it under the per-site secret and marks it LOCAL. posix_isatty( STDIN ), resolved once per session, chooses readline over fgets and suppresses the prompt and trailing newline on a pipe; a build without ext/readline gives a terminal prompts through show_prompt_fallback() and no history or completion.
2_router peels {type}.p{N} and the Partition named for the worker appends the packed record to input/{seg}.log. build_repl_graph() calls neither allow_large_writes() nor void_warranty() here, because several sessions append to one directory at once and an append under PIPE_BUF is atomic without a lock. Over MAX_LINE_SIZE (4096 bytes) — a large send_node or send_struct — the record is dropped with a rate-limited WARNING: oversize: on stderr, no error comes back, and the session looks unanswered. Feed bulk in through a job or wp nodes ingest.
3The worker's input Consumer tails input/ with a durable cursor in input.offsets/ (a first spawn seeks to the end, a respawn resumes, so a command queued across a recycle still gets its reply), prepends _repl to FROM and hands the command to the interpreter, which verifies the signature and runs the verb in the worker's own event loop. dump_node, connect_node and disconnect_node act on the running graph with no restart.
4The reply is addressed TO=_repl/_output/<pid>. _router peels _repl and that Partition writes output/ under void_warranty(): the worker is its only writer, so a whole dump_metadata fits. A verb that throws comes back the same way as TM_COMMAND|TM_ERROR.
5The cli's ephemeral Consumer (no offsetlog) tails output/, stamps {type}.p{N} on FROM and relays toward _output. The Dumper's TO filter matches (?:_output/)?<pid>, so every other session's reply falls through silently and an empty TO renders as an unaddressed broadcast. It carries the rendered line to _stdout by target, never down a sink chain (ADR-7); STDOUT on a pty is non-blocking because it shares STDIN's open file description, so Stdout_Node::write_all() waits for the buffer to drain rather than dropping. An error renders on stdout like any reply, so wp nodes cli … | grep sees it.
6On stdin EOF the cli mints a TM_EOF through the Shell; the receiving interpreter bounces it TO=FROM, the Dumper sees the echo and flips the exit flag. Pivoted, that round trip rides both partitions, so every earlier reply has been read off disk before the cli exits, with no sleep slack. A 5-second deadline is the fallback for a dead worker; the cli exits anyway once it passes.

Bare: wp nodes cli with no worker

The first two lanes alone: the same local nodes, no IPC pair, and every command runs in the wp-cli process at secure level 0. Use it to exercise interpreter verbs without touching a worker.

Both refuse root

Workers run as the web user and own their lock and IPC directories. A root cli would seed {base}/ipc/{type}.p{N}/input/ as root, leaving the workers unable to append to their own IPC. Recover with chown -R <web-user>:<web-user> {base}.

Many sessions, one worker

Fine: each session's outbound Partition appends to the same input/ atomically, and the pid filter in step 5 keeps each session's replies to itself.
