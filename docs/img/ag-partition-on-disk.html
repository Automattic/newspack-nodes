A Partition is a directory of segments, and fill() is the only way bytes get in

Every producer in the runtime reaches disk through this class: Log extends it, Topic fans into N of them, a worker's IPC is one. The write path batches to PIPE_BUF, rotates at segment_size, and prunes by three rules over a floor of two segments.

On disk

Segments are ids sorted numerically (SEGMENT_PATTERN /^(\d+)\.log$/); rotation is monotonic. No .idx exists unless a formatter is installed, and there is no binary index format.

read_at( seg, off, len ) seeks into a .log; scan_index() walks the .idx lines; index_mtimes() stats each .idx fresh, the one clock a reader owns on a hub.

The write path: fill( $message )

1
Pack. Message::packed() + "\n". Every TYPE passes, TM_REQUEST, TM_ERROR and TM_EOF included: the IPC bus depends on it. Event_Framework::pump() runs here, so a long write loop still hears its stop.
2
Size the FINAL bytes. Over MAX_LINE_SIZE 4096 the record is dropped, unless the cap was lifted to MAX_LARGE_LINE_SIZE 32 MiB by one of the two opt-ins below. A record over 4 KB on a lifted partition bypasses the batch: PIPE_BUF cannot be preserved for it, and the held Lock serializes it against the small flushes.
3
Batch in memory. If $batch + the new record would exceed 4096, the batch flushes FIRST and the record starts a fresh one, so each fwrite stays one atomic PIPE_BUF unit. A 0 ms one-shot timer (set_timer( 0, true )) lands whatever is left when the loop iteration ends; __destruct() and Topic::flush() land it in request scope.
4
Rotate when the segment passes segment_size (default 64 MiB), then run retention. maybe_rescan_segments() re-reads the directory at most once per DRIFT_RESCAN_INTERVAL_SECONDS 1.0 to follow a peer's rotation; readers see the list cached for SEGMENT_CACHE_TTL 0.25 s.
!
A short write is quarantined, never swallowed. File_Writer::write_all() returns the bytes landed and retries up to MAX_WRITE_ATTEMPTS 5 so a full disk cannot spin the loop; recover_write_stall() truncates the torn record off the segment, since it would desync every reader after it, and dead-letters every message that did not land whole, replayable with wp nodes ingest. Sidecars opt out via without_write_deadletter(): a quarantine that quarantines chains forever on a full disk.

Three retention rules over a floor of two, oldest first

01234567

segments 0 and 1 pruned; 6 and 7 are the two the floor always keeps, 7 being written

ageolder than lifetime, keeping at least min_segments
countmore than num_segments, sparing anything younger than min_lifetime
hard capmore than max_segments: UNCONDITIONAL, min_lifetime does not protect, only the floor of 2 does. 0 derives to 2 × num_segments

A low-traffic partition keeps segments for days under the age and count floors. Documented, not a bug.

The declared geometry is normalized UPWARD before any rule runs

1 · min_segmentsrises to MIN_SEGMENTS_FLOOR 2
2 · num_segmentsrises to min_segments
3 · max_segmentsderive_max_segments() raises an explicit value to num_segments; the 0 sentinel derives 2 × num_segments

So num_segments 1 runs as 2, and min_segments 5 num_segments 3 max_segments 4 runs as 5 / 5 / 5. derive_max_segments() is public so the admin and CI ceilings agree with cleanup_segments().

Positional order: dir segment_size min_segments num_segments max_segments min_lifetime lifetime — max_segments precedes the two lifetimes.

allow_large_writes( $max_wait_ms = 15000, $debounce_ms = 0 ) — lift the cap behind a Lock

Takes a Lock at {dir}/write.lock.d/, blocking up to DEFAULT_LOCK_WAIT_MS 15 s: long enough for an external writer to ride out a burst, short enough that a web request never hangs. It does not outwait a crashed holder, whose dir becomes stealable only after LOCK_STALE_TIMEOUT_SECONDS 60; a worker passes 0 (try-lock) and retries next tick.

Hold mode ($debounce_ms = 0): acquire up front, hold for the partition's life. Debounced (> 0): fill() takes the lock at the start of a burst and fire() frees it after that much quiet. There is no with_lock() wrapper: in a drain loop the {name}:heartbeat Timer refreshes the Lock; in request scope fill() heartbeats inline at most once per stale_timeout/3 s and throws if the lock was stolen.

void_warranty() — lift the cap with NO lock

The caller asserts it is the sole writer. Nothing enforces it: a second writer is the silent torn write ADR-4 warns about. The worker's _repl output Partition runs this way, which is what lets a dump_metadata reply reach an attached cli.

On a Topic both verbs record the mode and re-apply it to every partition materialized later; Topic::allow_large_writes( $debounce_ms = 0 ) exposes no timeout and always passes 15 s down, so the FIRST message routed to an index can block and then throw straight out of fill().
