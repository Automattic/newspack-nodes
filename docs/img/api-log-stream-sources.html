A log source is a registry name, never a path

GET /log/stream and the REPL's taillog verb read the same Log_Sources registry, so a caller has no traversal surface. Three families merge in priority order, each entry carries one of two tail modes, and one read model answers both single-step readers.

Log_Sources::open_tail(), the one place the mode token becomes a class

file → File_Tail_NodeFollows one filename with tail -F semantics. The file's INODE occupies the cursor's segment slot, so <inode>:<offset>:<length> rides the existing offsetlog frame; a mismatch re-seeks to 0 rather than read a rotated-away generation. recent folds to the start, since one file has no previous segment.
segmented → Tail_NodeReads {file}.{seg} as a segment series. This is why Tail_Node::node_schema() declares no mode argument an operator could set: the registry entry decides.

One read model, two verbs

taillog read <source> <position> and raw-logs read_message <log> <position> both run Log_Sources::read_at() and answer the same struct:

{ source, message, cursor: { segment, offset }, at_eof }
// message: the packed 7-field Message
// cursor: the POST-step position, where the next step resumes

A position is <segment>:<offset> with an optional :<length> that is tolerated and IGNORED, the reader knowing the record's real length, or one of start, recent and end (Log_Sources::MAGIC_POSITIONS, aliasing Consumer_Node::SEEK_*). The reader arrives already armed, so read_at() sinks its own Callback_Node and removes it in a finally on every exit; a reader left armed with no sink fires forever inside the worker's drain loop.

Failures come back as a STRING, not a throw

<verb>: invalid position (want <segment>:<offset>[:<length>], start, recent or end)
<verb>: no record at <source> <position>
unknown log source …  — taillog read only; read_message resolves an unknown key to a catalog key instead

Every caller handles string-or-array: the teaching error is the verb's successful TM_RESPONSE value, one of the deliberate exceptions to the rule that a refusal throws. The stream route needs none of this: an unknown subscribe name throws the same unknown log source error listing the names that exist, no globs are accepted because registry sources are fixed for the life of a stream, and Tail's missing-file grace covers a source that appears, rotates or truncates mid-stream.

multi_writer is accepted and inert here: the route registration is inherited unchanged, but a subscription resolves to a Tail, and the seal grace belongs to a Consumer.
