Anatomy of a message

One PHP array with seven numbered slots. It crosses a process boundary as a JSON list of seven, and the receiver accepts a seven-element list and nothing else.

The wire form: one JSON array, read through Message::TYPE … Message::VALUE, never a bare number or a string key
[ 0type, 1timestamp, 2FROM, 3TO, 4id, 5key, 6value ]
SlotWhat it holdsWho writes itWho reads it
0Message::TYPE A bitmask of the eleven flags below. Flags combine: a reply to a command carries TM_COMMAND and TM_RESPONSE together. The minter. Any node that branches on it. The command interpreter tests for TM_COMMAND.
1Message::TIMESTAMP The moment of minting. The minter. The signature check on a command, which bounds how old it may be.
2Message::FROM A slash-separated path of names: the trail behind the message. The minter writes its own name. Each process boundary crossed puts one more name in front; forwarding inside one process adds nothing. A node that answers copies it into the reply's TO. The router drops one longer than 1,024 bytes.
3Message::TO A slash-separated path of names: the path ahead. Empty at minting. The node's target fills it when it is empty; a reply carries the request's FROM. The router splits it at the first slash and peels one segment per hop. An empty TO at the interpreter means the command is for this process.
4Message::ID An identifier the producer owns. The producer. Copied unchanged into the reply.
5Message::KEY What the producer groups on. The producer. Copied unchanged into the reply.
6Message::VALUE The data. For a command, the verb's name and its arguments. The producer. The node the message finally reaches.

An equality check misses every combination

A reply to a command has type TM_COMMAND | TM_RESPONSE, which is 8 + 256 = 264. 264 === TM_RESPONSE is false, and the reply is never recognised as an answer.

A bitwise AND finds the flag

264 & TM_RESPONSE is 256, which is true. Every node tests a flag this way, so a message carrying several flags satisfies every test it should.
