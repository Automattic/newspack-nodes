No ack: the synchronous drain is the backpressure, and the reader's cursor owns "safe to resume"

Tachikoma's TM_PERSIST, answer() / cancel() and max_unanswered earn their keep where a queue that can fill sits between producer and consumer. Here every boundary is synchronous and the whole graph drains on one CPU, so an ack would have nothing to signal.

Rejected: the persist / ack handshake (Tachikoma)

← answer() or cancel(): a TM_PERSIST | TM_RESPONSE sent TO=FROM, carrying the message's ID

Consumption is asynchronous from delivery, so the queue cannot know on its own when a message is safe to discard. The ack IS the tier's advance-or-discard signal: the reply decides what the Buffer keeps — a cancel deletes the entry from its store — and the unanswered count is the flow control.

Kept here, it would have no queue to guard: the synchronous single-threaded drain already slows every producer upstream of a slow node, and nothing between them can overflow.

↺ the next poll() waits for all of it: a slow handler stalls its worker's drain, which is the flow control, not a defect

"Delivered" and "safe to advance" coincide because both happen in the drain that dispatched the message. The reader owns its cursor entirely, so resuming is always local knowledge. Durability comes from the log and offsetlog tier; the message layer promises no at-least-once.

The one reply-control flag: TM_NOREPLY

A Shell with want_reply( false ) — topology load and script mode — ORs it onto every command it mints, and the interpreter suppresses the reply, still surfacing a failure on stderr as error from TM_NOREPLY command:.

Without it a worker's boot-topology replies route to _output/<pid>, which no worker has, and bounce a dropped NOT_AVAILABLE every startup.

Where flow control belongs

Slot-based flow control belongs at the producer that needs it, never graph-wide. TM_PERSIST is not a rival to the durable tier: in Tachikoma the ack is that tier's advance signal, needed only because consumption there is asynchronous from delivery.

Revisit if any one holds

A producer needs genuinely decoupled queueing; the drain stops being single-threaded; or offset advance is decoupled from delivery — async handlers, in-flight windows. Each breaks the "delivered = safe to advance" coincidence the removal rests on.
