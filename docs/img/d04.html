A worker's 595 seconds

A worker is a PHP request that outlives its caller. It crosses one gate, takes a lock, drains messages until a predicate says stop, and releases the lock before it POSTs its own successor.

Record the accepted spawn in the shared cache, which is memcached, falling back to APCu and then to a transient. The refusal holds against whoever sends the second POST.

Self-respawn, a peer's revival and the cron pass all POST this one endpoint, so a single gate throttles every tier.

A directory already held means this worker exits as skipped, so one process runs each slot.

A heartbeat older than the topology's stale timeout marks the holder dead and frees the lock to a peer. The default is 60 s; the job-worker topology uses 600 s, because a CPU-bound job reaches no heartbeat point.

The heartbeat rides inside the same call

A process that asks whether to keep running proves it is alive. A long job asks from inside its work, so it heartbeats and stops on time.

Release before respawn, never after

Reversed, the successor meets a lock this process still holds, exits as skipped, and the slot idles until a peer's scan notices.

Three stops decline the respawn

An operator stop, which must leave the slot empty for a deploy. An on-demand idle exit, which has no work. A topology that fails to load, which would loop on the same bad file.

A death before the finally leaves nothing behind

An out-of-memory kill checkpoints no cursor and releases no lock. The safety net covers that case.
